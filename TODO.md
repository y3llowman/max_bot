## 2. Что показывать на защите (исходя из 3 дней)

Сквозной сценарий: **ИНН → профиль собран автоматически → лента подходящих обязанностей → карточка с деталями → документ пришёл в чат → напоминание в чат → «Сделано» кнопкой в чате.**

Всё, что зависит от реального времени (напоминание за 30 дней, исключение из МСП, проверка в ЕРКНМ), показывается **командами-триггерами для демо**. Ждать 30 дней на защите нельзя.

#### ☐ 1. Каталог обязанностей (новый файл `backend/radar/obligations.py`)
Это ядро продукта. Нужно 10–15 обязанностей, записанных как данные плюс правило применимости.

```python
@dataclass(frozen=True)
class Obligation:
    code: str                      # "usn_decl", "rsv", "efs1_td", "quota"...
    title: str                     # «Декларация по УСН»
    what: str                      # что нужно сделать, 1–2 предложения
    how: tuple[str, ...]           # пошаговая инструкция
    where: str                     # «ФНС» / «СФР» / «Госуслуги»
    where_url: str
    format: str                    # «Только электронно» / «Бумажный оригинал + электронная копия»
    basis: str                     # «181-ФЗ, ст. 21»
    basis_url: str                 # consultant.ru / pravo.gov.ru
    penalty: str | None            # «от 5% неуплаченного налога, но не менее 1 000 ₽ (ст. 119 НК)»
    periodicity: str               # once | monthly | quarterly | yearly
    applies: Callable[[Profile], str | None]    # None — не касается; строка — ответ на «почему я это вижу»
    due_dates: Callable[[date, date], list[date]]  # сроки в окне [from, to]
    document: str | None = None    # код шаблона для «Подготовить документ»
```

- Что покрыть: декларация по УСН (у юрлица и ИП сроки разные), авансы по УСН, ЕНП (28-е число), уведомления об исчисленных суммах (25-е), РСВ, 6-НДФЛ, ЕФС-1 (СЗВ-ТД) — эти три только при наличии сотрудников, бухотчётность (только юрлица), НДС (ОСНО), квота по инвалидам (зависит от численности), СОУТ, ЭПД (ОКВЭД 49.4), ККТ.
- Если срок выпадает на выходной, переносить на следующий рабочий день (п. 7 ст. 6.1 НК). В `payload` класть `shifted` и `original`: шаблон `deadline.group` уже умеет их показывать.
- ⚠️ **Все сроки и пороги проверьте по налоговому календарю ФНС.** Пример: в ТЗ квота «свыше 25 человек», а по ст. 21 181-ФЗ федеральный порог — **35**. Регион может ввести квоту с 25 (до 3%). Значит, правило должно зависеть от региона.

#### ☐ 11. «Запросить у контрагента»
Ответ на вопрос из ТЗ «технически возможно?»: **бот MAX не может написать первым** человеку, который его не запускал. Поэтому схема такая:
- таблица `counterparty_requests(id, token, event_id, from_user_id, text, status, reply)`;
- кнопка создаёт запрос и открывает «Поделиться» ссылкой `https://max.ru/<бот>?start=req_<token>`. Формат диплинка с параметром для бота проверьте на dev.max.ru;
- контрагент открывает бота и видит карточку с кнопками «Отправлю» / «Не могу» (или прикладывает файл). Бот уведомляет того, кто запрашивал. Статус задачи → `in_progress`.
