# Мини-приложение MAX

React 19 + TypeScript + Vite. Вёрстка по макетам из `design/` (светлая и тёмная темы,
iOS и Android), токены и типографика — из `design/UI Kit v2.svg`.

## Запуск

Нужен Node.js 20+.

```bash
cd frontend
npm install
npm run dev
```

Откроется `http://localhost:5173`. Без `VITE_API_URL` приложение работает на моках —
тех же данных, что на макетах: «сегодня» 22 июля 2026, компания «Северный ветер».

```bash
npm run typecheck   # строгая проверка типов
npm run build       # сборка в build/ — статика для любого HTTPS-хостинга
```

## Настройки

Скопируйте `.env.example` в `.env`:

| Переменная | Зачем |
|---|---|
| `VITE_MAX_BOT_NAME` | Имя бота: «В чат MAX» открывает `https://max.ru/<имя>` |
| `VITE_API_URL` | Адрес API. Пусто — моки из `src/api/mock.ts`; `/api` — бэкенд. Для `npm run build` уже задан в `.env.production` |

## Работа с бэкендом

1. Поднимите FastAPI из репозитория бэкенда на `localhost:8000`.
2. В `.env` этой папки: `VITE_API_URL=/api`.
3. `npm run dev` — Vite проксирует `/api` на `localhost:8000`, отдельный CORS не нужен.

Задавайте `VITE_API_URL` в файле `.env`, а не в команде. Git Bash на Windows молча
превращает `VITE_API_URL=/api npm run dev` в `C:/Program Files/Git/api`, и все запросы
падают с «Нет соединения». Если всё же в команде — с префиксом `MSYS_NO_PATHCONV=1`.

Вне клиента MAX `initData` пустой, поэтому с настоящим бэкендом приложение покажет
«Откройте приложение в MAX» — войти без подписи мессенджера нельзя, так и задумано.
Для ревью вёрстки в браузере оставляйте `VITE_API_URL` пустым — работают моки.

Сборка кладётся в `build/`, и есть пустой скрипт `prepare` — ровно то, что ждёт
Dockerfile шаблона бэкенда (`npm run prepare && npm run build`, копирует `build/`).
Поэтому папку можно поставить на место `frontend/` без правок Dockerfile.

Папка утилит называется `src/utils`, а не `src/lib`: корневой `.gitignore`
бэкенд-репозитория содержит правило `lib/` из питоновского шаблона и молча
исключил бы её из коммита.

## Ревью дизайна в браузере

Вне клиента MAX приложение рисует шапку мессенджера само (крестик / стрелка, название,
галочка) — чтобы экраны выглядели как макеты. Внутри MAX её нет: шапку рисует клиент.

Параметры в адресе, комбинируются:

| Параметр | Что делает |
|---|---|
| `?state=loading` | Скелетоны загрузки — S1, S4 |
| `?state=empty` | Пустые состояния — S2, S6 |
| `?state=error` | Ошибки — S3, S5 |
| `?theme=dark` / `light` | Тема независимо от системной |
| `?platform=ios` / `android` | Вариант таббара: iOS или Android с пилюлей |
| `?today=2026-07-22` | «Сегодня» для моков |

Пример: `http://localhost:5173/?state=error&theme=dark#/tasks`

Демо-сценарии на моках:
- ИНН с правильной контрольной суммой, например `7701234560`, — подключение;
- `0000000000` — «Не нашли компанию с таким ИНН»;
- на задаче «Декларация по НДС» — «Уже подано» → тост с отменой → через 5 секунд «Готово».

## Диплинки

Бот открывает приложение ссылкой `https://max.ru/<бот>?startapp=<payload>`.
Payload — до 512 символов, только `[A-Za-z0-9_-]` (ограничение MAX):

| Payload | Куда |
|---|---|
| `task_<id>` | Задача — так открывать из уведомления о сроке |
| `calendar`, `notifications`, `profile` | Разделы |

Поэтому id задач на бэкенде — только латиница, цифры, `_` и `-`.

## API

Пути ниже — относительно `VITE_API_URL` (например, `/api/session`).
Типы ответов — `src/api/types.ts`.

Авторизация — по схеме бэкенда. При первом запросе фронтенд меняет `initData`
из MAX Bridge на JWT через `POST /user/auth` `{ initData }` → `{ access_token }`;
бэкенд проверяет подпись (dev.max.ru/docs/webapps/validation). Дальше все запросы
идут с `Authorization: Bearer <токен>`. Токен живёт только в памяти. На 401 фронтенд
один раз входит заново и повторяет запрос; параллельные запросы делят один вход.

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/session` | `Company`; 404 — компания не подключена |
| POST | `/session` `{ inn }` | `Company`; 404 — ИНН не найден в реестре |
| GET | `/dashboard` | `DashboardData` |
| GET | `/tasks/:id` | `TaskDetails`; 404 — задачи нет |
| GET | `/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` | `Task[]`, включая выполненные |
| GET | `/company` | `Company` |
| POST | `/company/refresh` | `Company` — перечитать данные из ФНС |
| GET / PUT | `/settings/notifications` | `NotificationSettings` |
| POST / DELETE | `/tasks/:id/submitted` | 204 — «Уже подано» и его отмена |
| POST | `/tasks/:id/document` | 204 — сформировать документ, бот пришлёт его в чат |

Группировку «Сегодня / На неделе» и подписи сроков («был 20 июля», «до 27 июля»)
делает клиент — бэкенд отдаёт только даты и статус (`overdue` / `soon` / `planned` / `done`).

## MAX Bridge

`src/max/bridge.ts` — обёртка над `window.WebApp` по dev.max.ru/docs/webapps/bridge:
кнопка «назад» на вложенных экранах, `openMaxLink` для «В чат MAX», сканер QR для ИНН,
тактильный отклик, `start_param`. Вне MAX всё работает на заглушках.

Тему MAX не передаёт — в документации этого нет. Берём системную (`prefers-color-scheme`),
в «Профиле» можно выбрать вручную.

## Где вёрстка отличается от макетов

Осознанно, каждое — вопрос к дизайнеру:

- **02:** разделитель под текстом — сплошная линия. В макете две половины с зазором 12px
  без подписи между ними — похоже на остаток убранного блока «или Госуслуги».
- **Кнопки M — 48**, как на экранах состояний. В ките написано «M — 44».
- **Плитка «Скоро»:** иконка часов цветом `warning-strong`, как в S2 и тёмной теме.
  В 03 она `warning`.
- **06:** у кнопки обновления справа отступ 8px — в макете она прижата к краю блока,
  а сверху и снизу отступы есть.
- **03:** «Акт сверки» 24 июля попадает в «На неделе» — правило «ближайшие 7 дней».
  В макете дашборда его нет, хотя в календаре он есть.
- **E3:** добавлена группа «Позже» для сроков дальше следующей недели.
- **Проверка ИНН** — не только длина, но и контрольные цифры. ИНН из макетов
  `7701234567` контрольную сумму не проходит.

Тексты без макета — написаны по тону дизайнера, стоит вычитать: тосты «Сформировать» и
сбоев, «Задача не найдена», ошибка календаря, пустой список, «В этот день сроков нет»,
ошибка подключения на старте, вариант пустого дашборда «На неделе всё спокойно», чип
«Сохранено…» над сохранённой версией, «Контрагенты» (экрана нет — тост). Время тихих
часов и тема выбираются системным списком — отдельного экрана выбора в макетах нет.
