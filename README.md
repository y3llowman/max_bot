## Назначение

**Для кого.** Владелец микро- или малого предприятия либо ИП без штатного юриста и бухгалтера, который сам следит за налогами, отчётностью и проверками.

**Проблема.** О новых обязанностях и требованиях такой предприниматель узнаёт поздно и вслепую. Рассылки и новости пишутся для всех сразу, и каждый раз нужно разбираться, касается ли это его. Итог — часы на проверку либо пропущенный срок и штраф.

**Решение.** Человек присылает боту ИНН — и всё. Профиль компании (вид деятельности, категория МСП, численность, регион, лицензии) собирается сам из официальных открытых данных ФНС. Режим налогообложения бот уточняет одним нажатием: в открытых реестрах его нет. Дальше бот следит за изменениями и пишет только о том, что применимо именно к этой компании: подошёл срок, вышел закон, появилась плановая проверка. Он не только уведомляет: готовит черновик документа (.docx) и напоминает, пока задача не закрыта.

**Ожидаемый эффект** (гипотеза для пилота): время на выяснение «что и когда мне сдавать» — с часов до нескольких минут при подключении; число пропущенных сроков — к нулю, потому что напоминания идут, пока задача открыта. Метрики пилота: доля подключивших компанию, доля закрытых задач по напоминаниям, число просрочек до и после.

## Основной пользовательский сценарий

ИНН в чате → «Нашли вашу компанию … Всё верно?» → режим налогообложения (и численность, если её нет в реестре) кнопками → «📡 Радар настроен: N обязанностей, ближайший срок …» → короткие напоминания по одному, пока задача не закрыта → подробности, документ и «Выполнено» — в мини-приложении. Пошаговый вариант с ожидаемыми ответами — [ниже](#пошаговый-сценарий-проверки).

## Что умеет бот

**Чат (бот)** — регистрация, короткие пуши и решение одной кнопкой. Сообщения приходят по одному; на которое ответили — удаляется из чата, чтобы там оставалось только то, что ждёт решения.

| Команда или действие | Что происходит |
|---|---|
| «Начать», `/start` | Нет компании — просит ИНН. Есть — продолжает с места остановки |
| ИНН (10 или 12 цифр) | Проверяет контрольную сумму, находит компанию в реестре МСП, показывает карточку (название, ИНН, ОГРН, ОКВЭД, категория и численность, регион, лицензии, источник и дата данных) и спрашивает «Всё верно?». «Исправить» открывает экран «Данные компании» в приложении |
| Вопросы профиля | Режим налогообложения (ОСНО, УСН «доходы», УСН «доходы минус расходы», АУСН, патент для ИП) и численность — кнопками. От ответов зависит список обязанностей |
| `/profile` | Карточка компании, кнопки «Изменить данные» и «Открыть приложение» |
| Пуш | 2–3 строки: что случилось и главная дата. Кнопки: «📋 В список дел», «✅ Сделано», «🔕 Не актуально», «Открыть» (экран события в приложении) |
| Любой другой текст или фото | Подсказка, что делать |

**О чём бот пишет** — и только если это применимо к профилю компании:

- **Сроки обязанностей** (20 штук, сроки считаются с переносом с выходных и праздников): декларация и авансы по УСН, уплата налога по УСН, уведомление по НДФЛ и взносам, уплата ЕНП, персонифицированные сведения, РСВ, 6-НДФЛ, ЕФС-1, ЕФС-1 о стаже (АУСН), налог по АУСН, сведения о квоте для инвалидов (более 35 человек), бухгалтерская отчётность, декларация по НДС, налог на прибыль, 3-НДФЛ, авансы и уплата НДФЛ ИП на ОСНО, оплата патента, страховые взносы ИП. К каждой — «почему вам», шаги, куда сдавать, основание со ссылкой, штраф. Напоминания: за 30, 7, 1 день и в день срока (настраивается), после срока — каждый день, пока задача не закрыта.
- **Новые законы и приказы**: каждый день бот разбирает акты, опубликованные на pravo.gov.ru, и присылает компании только те, что её касаются (по режиму налогообложения, численности, ОКВЭД, региону; законы субъектов — только своему региону). В сообщении — «почему вам» и кнопка со ссылкой на официальный текст.
- **Проверки из ЕРКНМ**: плановые проверки, профилактические визиты, предостережения по ИНН компании — ночная сверка.
- **Реестр МСП**: исключение из реестра, смена категории (например, выход из микропредприятий — с новой обязанностью).
- **Документы**: кнопка «Подготовить документ» присылает в чат .docx — уведомление об исчисленных суммах, приказ о квотируемых местах, реквизиты платёжки на ЕНП или памятку к отчёту с реквизитами компании.

**Мини-приложение** — всё, что не помещается в чат: главная («Сегодня», «На неделе», «Список дел», счётчики), календарь (месяц, неделя, список), экран события (что это значит, почему вам, что сделать, куда сдавать, основание, штраф), лента всего, о чём писал бот, «Данные компании» (поправить найденное и вписать реквизиты для документов), «Уведомления» (когда напоминать, тихие часы), тема оформления, смена компании.

**Демо-режим** (`DEMO=true`, на демо-сервере включён): команда `/demo` проводит по 13 шагам на вашей компании; `/demo_remind`, `/demo_event knm`, `/demo_law` запускают отдельные части. Что в демо настоящее, а что имитация — в разделе [«Тестовые данные»](#тестовые-данные).

## Состав и архитектура

| Компонент | Технологии | Что делает |
|---|---|---|
| Бот, контейнер `max_bot` (`backend/bot`) | Python 3.12, maxapi (MAX Bot API, long polling) | Регистрация по ИНН, вопросы профиля, пуши с кнопками |
| Планировщик в процессе бота (`backend/notifications`) | APScheduler | Очередь сообщений раз в минуту, напоминания в 09:00, законы в 07:00, ЕРКНМ в 04:30, реестр МСП 11-го числа |
| Правила (`backend/radar`) | Jinja2, python-docx | Каталог обязанностей и расчёт сроков, детекторы изменений, разбор законов, тексты сообщений, документы |
| API, контейнер `max_backend` (`backend/app`) | FastAPI, SQLAlchemy async | REST `/api`, проверка подписи MAX, раздача собранного мини-приложения |
| Мини-приложение (`miniapp`) | React 19, TypeScript, Vite, MAX Bridge | Экраны для пользователя |
| База, контейнер `max_postgres` | PostgreSQL 17, миграции Alembic | Реестр МСП, компании, профили, события, очередь сообщений, законы |

```text
Пользователь MAX ──чат──► MAX Bot API ◄──long polling── max_bot (бот + планировщик) ──┐
      │                                                                                ├──► max_postgres
      └─ мини-приложение (HTTPS) ──► обратный прокси ──► max_backend (API + статика) ──┘
max_bot ──► открытые данные ФНС и ЕРКНМ (файлы), API publication.pravo.gov.ru
```

Вход в мини-приложение: MAX передаёт подписанную строку `initData` → `POST /api/user/auth` проверяет подпись токеном бота → JWT на 12 часов → остальные запросы с `Authorization: Bearer`. Идентификатор пользователя из браузера не принимается. Мини-приложение подключено к боту и не работает отдельно от него. Устройство кода и назначение каждого файла — в [CURRENT_STATE.md](CURRENT_STATE.md).

## Запуск одной командой

Нужны Docker с Compose v2 и токен бота MAX. Для работы внутри MAX мини-приложение должно быть доступно по HTTPS и привязано к боту (привязку делают организаторы — FAQ хакатона, п. 2).

```bash
git clone https://github.com/y3llowman/webapp_max_fastapi.git && cd webapp_max_fastapi
cp .env.example .env    # вписать MAX_TOKEN, SECRET_KEY (openssl rand -hex 32), POSTGRES_PASSWORD (openssl rand -hex 16)
docker compose up -d --build
```

Последняя строка запускает все три компонента. Без `MAX_TOKEN`, `SECRET_KEY` или `POSTGRES_PASSWORD` Compose остановится и назовёт, чего не хватает. Схему базы создают миграции при старте API; бот стартует, когда API ответил на `/health`. При первом старте API загружает в базу срез реестра МСП (`backend/data/msp_slice.xml`), а бот за 5–10 минут догружает акты pravo.gov.ru за 30 дней.

Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok"}`; `docker compose ps` — `max_backend` `healthy`, `max_bot` `Up`.

**Время сборки.** С нуля без кэша, без загрузки базовых образов — 75 с при обычной сети (замер 29.09 днём). Почти всё время — загрузка пакетов из npm и PyPI. Ночью при медленном канале до registry.npmjs.org та же сборка шла около 300 с, из них 284 с — `npm ci`; шаг Python занимает 33 с.

**HTTPS на сервере.** Порт 8000 слушает только `127.0.0.1`; снаружи его отдаёт обратный прокси с сертификатом (Caddy, `/etc/caddy/Caddyfile`):

```
hackaton267max.webtm.ru {
    reverse_proxy 127.0.0.1:8000
}
```

## Параметры и переменные окружения

Обязательные параметры окружения: три секрета в `.env` (`MAX_TOKEN`, `SECRET_KEY`, `POSTGRES_PASSWORD`), выход в интернет (открытые данные и MAX) и HTTPS-адрес мини-приложения, привязанный к боту. Шаблон — [`.env.example`](.env.example), настоящих значений в репозитории нет.

| Переменная | Обязательна | Значение |
|---|---|---|
| `MAX_TOKEN` | да | Токен бота MAX. Им бот получает сообщения и отвечает, а API проверяет подпись `initData` |
| `SECRET_KEY` | да | Ключ подписи сессий мини-приложения, не короче 32 символов: `openssl rand -hex 32` |
| `POSTGRES_PASSWORD` | да | Пароль базы, только латиница и цифры (входит в URL подключения): `openssl rand -hex 16`. Действует с первого создания тома базы. Если том уже создан с другим паролем — сначала `docker compose exec postgres psql -U max -d maxapp -c "ALTER USER max PASSWORD '<новый>'"`, потом `up` |
| `APP_URL` | нет | HTTPS-адрес мини-приложения, привязанный к боту. Кодом не читается: мини-приложение и API отдаёт один контейнер |
| `DEMO` | нет, `true` | Демо-команды бота: `/demo`, `/demo_remind`, `/demo_event`, `/demo_law`, `/laws` |
| `MSP_FULL_REFRESH` | нет, `false` | `true` — 11-го числа бот сам скачивает свежий полный набор реестра МСП вместо среза (~2,1 ГБ, ~5 ГБ места в базе). Разово: `docker compose exec bot python backend/load_msp_registry.py --full` |
| `LAW_PDF` | нет, `false` | `true` — к сообщению о законе прикладывается PDF официального текста. Выключено, причина — в [ограничениях](#известные-ограничения) |
| `DEBUG` | нет, `false` | `true` — подробные логи и трассировки. На сервере не включать |
| `MAX_INIT_DATA_MAX_AGE` | нет, `86400` | Сколько секунд подпись MAX считается свежей |
| `DATABASE_URL` | только без Docker | В Docker собирается в `compose.yaml`. Без Docker: `postgresql+asyncpg://max:<пароль>@localhost:5433/maxapp` |

### Срез реестра МСП и что не подключено

Ради выполнения правил в MVP **нет обращений к сайтам ФНС и pravo.gov.ru через их внутренние запросы**. Отсюда три решения:

1. **Реестр МСП — срез.** Полный набор весит 2,1 ГБ (7519 XML-файлов, ~6,7 млн записей). На демо-сервере лежит срез из 10 настоящих компаний, вырезанных из набора на 10.09.2026 без изменений, в исходном формате ФНС — [`backend/data/msp_slice.xml`](backend/data/msp_slice.xml). ИНН не из среза бот не подключает и честно отвечает «нет в срезе реестра МСП», а не «нет в реестре». Возможность работать по полному набору есть: `MSP_FULL_REFRESH=true` (ежемесячно, автоматически) или `load_msp_registry.py --full` (разово). Разбор проверен на настоящих файлах архива (4500 записей организаций и ИП), скорость загрузки — [ниже](#работа-с-данными).
2. **ЕГРЮЛ не подключён.** Бесплатного документированного API у ФНС нет: сайт выписок рассчитан на людей, для информационных систем ФНС продаёт отдельный доступ. Поэтому КПП, адрес и руководителя для документов пользователь вписывает сам («Данные компании»), а события ЕГРЮЛ (недостоверность сведений, дисквалификация, ликвидация, смена руководителя) в MVP показывает только `/demo` — как имитация с пометкой.
3. **Законы — без текста.** В документации pravo.gov.ru нет метода, отдающего текст акта; полнотекстовый поиск на 30.09.2026 возвращает 0 результатов. Поэтому тема акта определяется по названию и названию изменяемого акта, дата вступления в силу не определяется, а вместо PDF-файла бот даёт кнопку-ссылку на официальную страницу акта. Скачивание PDF по ссылке сайта написано, но выключено (`LAW_PDF=false`): мы не уверены, что оно допустимо.

**Как это масштабируется и сколько стоит (для продакшна):**

| Данные | Официальный канал | Стоимость |
|---|---|---|
| Реестр МСП, все компании | Открытые данные ФНС — загрузка уже реализована | 0 ₽, ~5 ГБ в базе |

## Работа с данными

- **Что хранится** (PostgreSQL): реестр МСП (`msp_registry`, в MVP — срез) и журнал его загрузок; пользователь MAX (id, имя, username, фото, язык, настройки уведомлений); подключённая компания и снимок её записи для ежемесячного сравнения; ответы пользователя (режим, численность, поправки к реестру, реквизиты: КПП, адрес, руководитель); события и сроки; очередь и история сообщений; разобранные законы.
- **Откуда.** Факты берутся из открытых данных ФНС и ЕРКНМ и из API pravo.gov.ru, в сообщениях указан источник и дата («реестр МСП, срез открытых данных ФНС на 10.09.2026»). Сроки и «почему вам» — расчёт бота по правилам из `backend/radar/obligations.py` со ссылкой на статью. Режим и численность (если её нет в реестре) — ответ пользователя, помечается «указан вами». Расчёт бота, факт из реестра и рекомендация в интерфейсе не смешиваются.
- **Загрузка реестра.** Полная загрузка идёт одной транзакцией, пока она идёт, поиск отвечает по старым данным. Скорость: 300 000 записей за 12 с, полный набор — порядка 5–15 минут. Скачивание — потоком, по ссылке из паспорта набора.
- **Доступ.** Мини-приложение видит только компанию своего пользователя: вход по подписи MAX, каждый запрос проверяет принадлежность события его компании. Одну компанию ведёт один аккаунт MAX. Секреты — только в `.env`, база слушает только локальный интерфейс.
- **Сроки хранения.** Лента показывает 90 дней; сроки создаются на 365 дней вперёд. Автоудаления старых данных в MVP нет.
- **Схема** меняется миграциями Alembic (`backend/migrations`), при старте база обновляется до последней ревизии; база, созданная до Alembic, подхватывается сама.

## Тестовые данные

- **Компании — настоящие.** Срез реестра МСП — 10 записей из официального набора ФНС на 10.09.2026 без изменений. Список и ожидаемые ответы — [`test-data.json`](test-data.json). Для сценария в MAX — `7743212897` (ООО «Манилла Рест», микропредприятие, ОКВЭД 56.10, Москва, 1 человек) и `1650273744` (ООО «Камская строительная компания», малое предприятие, ОКВЭД 41.20, Татарстан, 8 человек). Для ошибок: `7707083890` — неверная контрольная сумма, `7707083893` — верный ИНН, но нет в срезе. `3666155612` — только для проверки API, чтобы не занять компанию сценария.
- **Одну компанию ведёт один аккаунт MAX.** Если ИНН уже подключён другим аккаунтом, бот ответит «Эту компанию уже подключил другой пользователь MAX». Освободить ИНН на сервере:
  ```bash
  docker compose exec postgres psql -U max -d maxapp -c "update notifications set status = 'cancelled' where status = 'pending' and event_id in (select id from radar_events where inn in ('7743212897','1650273744')); delete from user_businesses where inn in ('7743212897','1650273744')"
  ```
- **Настоящее и имитация.** Настоящие: реестр МСП (срез), механизм проверки ЕРКНМ (проверен на реальных данных за сентябрь 2026, но у 10 компаний среза записей в ЕРКНМ сейчас нет — реальный пуш о проверке они не получат), законы pravo.gov.ru, сроки и документы. **Имитация** — только события ЕГРЮЛ и часть событий реестров в `/demo` и `/demo_event`: у демо-компании нет реальной недостоверности, дисквалификации или исключения, поэтому тур строит их теми же детекторами из подставных выписок. В базе у них `source = "demo"`, на экране события — «Имитация для демо», кнопка «🧹 Убрать демо-события» их удаляет.
- **Демо-сроки.** `docker compose exec backend python backend/seed_demo_tasks.py <ИНН>` добавляет просроченную, сегодняшнюю и выполненную задачу с подписью «Демо · …».
- **Пересборка среза** из скачанного архива набора: `python backend/load_msp_registry.py --zip <архив.zip> --make-slice --inn <ИНН> …`.

## Проверка собственного API

Через эти методы работает мини-приложение. Описание — [`openapi.json`](openapi.json) (OpenAPI 3.1; выгружается из кода командой `python backend/export_openapi.py`, тест `test_openapi.py` падает, если файл устарел), проверки — [`DATA-API.yaml`](DATA-API.yaml) (23 проверки: метод, путь, параметры, роль, ожидаемые коды и поля), данные — [`test-data.json`](test-data.json).

Тестовая учётная запись — пользователь MAX `9000000000000000001` (роль `user`). Паролей в API нет: вход по `initData`, подписанному токеном бота, как это делает клиент MAX. Токен для проверки:

```bash
MAX_TOKEN=<токен бота> python backend/sign_init_data.py > init_data.txt
curl -s -X POST https://hackaton267max.webtm.ru/api/user/auth -H "Content-Type: application/json" \
     -d "{\"initData\": \"$(cat init_data.txt)\"}"          # {"access_token":"eyJ…","token_type":"bearer"}
curl -s https://hackaton267max.webtm.ru/api/user/me -H "Authorization: Bearer eyJ…"
```

Скрипту нужны Python и `python-dotenv`. Подпись действует 24 часа, токен — 12. Коды: 401 — нет токена или подпись неверна; 404 — компания не подключена, событие не найдено или ИНН нет в срезе (`detail` «INN not found in the SME registry slice loaded in this MVP»); 409 — компанию ведёт другой пользователь; 422 — неверные данные (ИНН с ошибкой в контрольной сумме, неизвестный режим, КПП не из 9 цифр). `POST /api/tasks/{id}/document` у тестового пользователя вернёт 502: MAX не может отправить файл несуществующему аккаунту.

## Известные ограничения

- **Реестр МСП в MVP — срез из 10 компаний.** Остальные ИНН бот не подключает. Полная загрузка реализована, но на демо-сервере выключена (`MSP_FULL_REFRESH=false`): ~5 ГБ места ради проверки не нужны.
- **ЕГРЮЛ не подключён:** реквизиты вводит пользователь, события ЕГРЮЛ — имитация в `/demo`.
- **Законы без текста:** тема по названию и изменяемому акту, а не по смыслу поправок; дата вступления в силу не определяется; часть актов «О внесении изменений в отдельные законодательные акты» остаётся без темы; PDF не прикладывается. Акты, вышедшие до подключения компании, не досылаются.
- **ЕРКНМ:** у ИП ИНН в открытых данных замаскирован — проверки ИП не находятся.
- **Одну компанию ведёт один аккаунт MAX** — тот, кто первым подключил ИНН. В рабочей версии владельца нужно подтверждать через Госуслуги (ЕСИА).
- **Режим налогообложения** в открытых данных отсутствует: бот спрашивает его у пользователя. Численность есть не у всех.
- **Документы** — черновики и памятки, суммы налогов бот не считает. Сроки сверены с календарём на 2026 год; переносы выходных 2028 года — после постановления Правительства.
- **Один экземпляр бота на токен:** два запущенных бота с одним `MAX_TOKEN` делят сообщения между собой.
- **Мини-приложение открывается только внутри MAX** (вход по подписи `initData`); в обычном браузере — экран «Откройте приложение в MAX».
- **Демо-команды доступны всем пользователям бота** (`DEMO=true`) — оставлены для проверки.
- **Сборка образа** зависит от канала: 75 с при обычной сети, около 300 с при очень медленном доступе к npm (лимит правил — 5 минут).

## Остановка и повторный запуск

```bash
docker compose stop                        # остановить всё, данные сохраняются
docker compose start                       # запустить снова
docker compose restart bot                 # перезапустить один сервис: bot, backend или postgres
docker compose logs -f --tail 200 bot      # логи (backend, postgres — так же)
git pull && docker compose up -d --build   # обновить версию, миграции применятся сами
docker compose down                        # удалить контейнеры, база в томе postgres_data остаётся
docker compose down -v                     # удалить контейнеры вместе с базой
```

Все сервисы перезапускаются сами (`restart: unless-stopped`). Напоминания, пропущенные, пока бот не работал, отправляются при его старте. Логи Docker ограничены: 5 файлов по 10 МБ.

## Разработка и тесты

Нужны Python 3.12+, Node.js 20+, PostgreSQL.

```bash
pip install -r requirements.txt
python backend/main.py                   # API на :8000; мини-приложение берёт из miniapp/build
python backend/bot/main_longpooling.py   # бот и планировщик

Новая миграция после изменения моделей: `cd backend && alembic revision --autogenerate -m "<что изменилось>"`.
