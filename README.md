# Радар обязанностей для малого бизнеса — бот и мини-приложение в MAX

Предприниматель узнаёт о новых обязанностях поздно и вслепую: рассылки и новости пишутся для всех сразу, и каждый раз приходится разбираться, касается ли это его. Итог — часы на проверку или пропущенный срок и штраф.

**Что делает продукт.** Человек присылает боту ИНН — и всё. Профиль компании собирается сам из открытых государственных реестров: вид деятельности (ОКВЭД), категория МСП, численность, регион, лицензии, записи ЕГРЮЛ, проверки и предостережения из ЕРКНМ. Дальше бот следит за изменениями и пишет **только то, что касается именно этой компании**:

- подходит срок обязанности (декларации, уведомления, взносы, отчёты — 20 обязанностей, сроки считаются по режиму налогообложения, численности и типу компании);
- вышел закон или приказ, который её касается (ежедневный разбор publication.pravo.gov.ru, с объяснением «почему вам» и официальным PDF);
- в реестре появилась запись: недостоверность сведений в ЕГРЮЛ, дисквалификация руководителя, предстоящее исключение, плановая проверка или профилактический визит, исключение из реестра МСП, смена категории.

Бот не просто уведомляет: готовит черновик документа (.docx с реквизитами из реестров) и напоминает, пока задача не закрыта.

## Как это выглядит для пользователя

| | Бот (чат MAX) | Мини-приложение |
|---|---|---|
| Регистрация | ИНН → «Нашли вашу компанию» со всем найденным → «Всё верно?» → режим налогообложения и численность одним нажатием (их нет в открытых реестрах) → «📡 Радар настроен» | Подключение по ИНН или QR-коду; экран «Данные компании» — поправить найденное в любой момент |
| Что-то случилось | Короткий пуш: что случилось и главная дата. Кнопки «📋 В список дел», «✅ Сделано», «🔕 Не актуально», «Открыть». Сообщения приходят по одному, отвеченное удаляется | Экран события: что это значит, почему вам, что сделать, куда сдавать, основание со ссылкой, штраф; «Подготовить документ», «Выполнено», «В список дел» |
| История и планы | В чате — только то, что ждёт решения | Главная («Сегодня», «На неделе», «Список дел»), календарь, лента всего, что писал бот |
| Настройки | `/profile` — карточка компании | «Данные компании», «Уведомления» (когда напоминать, тихие часы), тема |

**Одну компанию ведёт один аккаунт MAX.** Если ИНН уже подключён другим аккаунтом, бот откажет: «Эту компанию уже подключил другой пользователь MAX». Перед сдачей освободите ИНН для жюри — на сервере:

```bash
cd /opt/webapp_max_fastapi
docker compose exec postgres psql -U max -d maxapp -c "select inn, user_id, connected_at from user_businesses"
docker compose exec postgres psql -U max -d maxapp -c "update notifications set status = 'cancelled' where status = 'pending' and event_id in (select id from radar_events where inn in ('7743212897', '1650273744')); delete from user_businesses where inn in ('7743212897', '1650273744')"
```

Первая команда показывает, какие ИНН сейчас заняты, вторая освобождает оба демо-ИНН (события и сроки компании остаются, ей просто больше никто не владеет).

## Сценарий проверки

Займёт 5–10 минут. Нужен аккаунт MAX: мобильное приложение, десктоп или веб-версия https://web.max.ru.

1. Откройте https://max.ru/t267_hakaton_max_bot → «Начать». Бот просит ИНН.
2. Пришлите `7707083890` → «Некорректный ИНН…». Пришлите `7707083893` → «Компанию с ИНН … не нашли в реестре МСП…».
3. Пришлите `7743212897` → карточка «Нашли вашу компанию»: название, ИНН и ОГРН, ОКВЭД, категория и численность, регион, лицензии, источник и дата данных — и вопрос «Всё верно?».
4. «✅ Да, всё верно» → вопрос о режиме налогообложения → «УСН доходы» → «📡 Радар настроен: N обязанностей», ближайший срок и кнопка «Открыть приложение».
5. «Открыть приложение» → главная: плитки «Просрочено / Скоро / Выполнено», задачи на сегодня и неделю (или «На 30 дней всё спокойно» с ближайшим сроком). Откройте задачу из календаря → разделы «Почему вам», «Что сделать», «Куда сдавать», «Правовое обоснование», «Риски при задержке» → «Подготовить документ» — .docx придёт в чат.
6. Профиль → «Данные компании» → «Численность» → «36–100 человек» → «Сохранить» → главная с тостом «обязанности пересчитали»; в календаре появилась квота для инвалидов.
7. Быстрый показ всего остального (работает при `DEBUG=true`, на сервере включено): `/demo` в чате — тур из 13 шагов на вашей компании: напоминания, документы, проверки ЕРКНМ, события ЕГРЮЛ и реестра МСП, новые законы с PDF, мини-приложение. События реестров в туре — имитация и помечены так, в конце их убирает кнопка «🧹 Убрать демо-события». Отдельные команды: `/demo_remind` — напоминания о ближайших сроках сейчас, `/demo_event knm` — запись о плановой проверке, `/demo_law` — настоящие акты pravo.gov.ru за 30 дней, которые касаются компании.
8. Под пушем: «📋 В список дел» — пуш уходит из чата, задача — в «Список дел» на главной; «✅ Сделано» — задача закрыта; «Открыть» — экран события в мини-приложении.

Подробный сценарий с ожидаемым результатом каждого шага — в [CURRENT_STATE.md](CURRENT_STATE.md#демо-сценарий-проверка-всех-функций).

## Запуск

Нужны Docker с Compose v2, бот MAX (токен — на платформе MAX для партнёров, раздел «Чат-боты») и, для мини-приложения, публичный HTTPS-адрес: MAX открывает мини-приложения только по HTTPS.

```bash
git clone https://github.com/y3llowman/webapp_max_fastapi.git
cd webapp_max_fastapi
cp .env.example .env
```

В `.env` впишите `MAX_TOKEN` и `SECRET_KEY` (`openssl rand -hex 32`), затем:

```bash
docker compose up -d --build
```

Сборка с нуля — около полутора минут (проверено: 75 с без кэша). Поднимаются три контейнера:

| Контейнер | Что делает |
|---|---|
| `max_postgres` | PostgreSQL 17, данные в томе `postgres_data` |
| `max_backend` | FastAPI: API мини-приложения (`/api`), собранное мини-приложение (`/`), `/health` |
| `max_bot` | Бот (long polling к MAX) и планировщик: напоминания, ночные сверки реестров, законы |

Таблицы создаются сами при первом старте, миграции вручную не нужны. После первого старта бот 5–10 минут загружает акты pravo.gov.ru за 30 дней (в логе `pravo.gov.ru: N new acts about business`).

Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok"}`; `docker compose ps` — у `max_backend` статус `healthy`.

**HTTPS и мини-приложение.** Порт 8000 открыт только на 127.0.0.1 — снаружи API и мини-приложение отдаёт обратный прокси с сертификатом. На сервере это Caddy (`/etc/caddy/Caddyfile`):

```
hackaton267max.webtm.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Адрес (`APP_URL`) указывается в настройках бота на платформе MAX как адрес мини-приложения. Если бот другой, перед сборкой поменяйте его ник в `miniapp/.env.production` (`VITE_MAX_BOT_NAME` — кнопка «В чат MAX»).

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `MAX_TOKEN` | да | Токен бота MAX. Им бот получает сообщения и пишет в чат, а API проверяет подпись `initData` мини-приложения |
| `SECRET_KEY` | да | Ключ подписи сессий мини-приложения, не короче 32 символов: `openssl rand -hex 32`. Без него `max_backend` не стартует |
| `APP_URL` | нет | HTTPS-адрес мини-приложения — тот, что указан в настройках бота на платформе MAX. Код его не читает: мини-приложение и API отдаёт один контейнер, запросы идут на относительный `/api` |
| `DATABASE_URL` | нет | В Docker задана в `compose.yaml`: `postgresql+asyncpg://max:max@postgres:5432/maxapp`. Значение из `.env` используется только при запуске без Docker (`localhost:5433`) |
| `DEBUG` | нет, по умолчанию `true` | `true` — демо-команды `/demo`, `/demo_remind`, `/demo_event`, `/demo_law`, `/laws`, Swagger на `/docs`, подробные логи API. Для боевого режима — `false` |
| `MAX_INIT_DATA_MAX_AGE` | нет, по умолчанию `86400` | Сколько секунд подпись мини-приложения от MAX считается свежей |

## Порты

| Порт на хосте | Контейнер | Что там |
|---|---|---|
| `127.0.0.1:8000` | `max_backend:8000` | Мини-приложение (`/`), API (`/api/...`), `/health`; Swagger `/docs` — при `DEBUG=true` |
| `127.0.0.1:5433` | `max_postgres:5432` | PostgreSQL (пользователь, пароль и база — `max` / `max` / `maxapp`) |

Оба порта слушают только локальный интерфейс: наружу — через HTTPS-прокси. Боту входящие порты не нужны. Исходящие соединения: `platform-api.max.ru` (бот), `rmsp.nalog.ru`, `egrul.nalog.ru`, `proverki.gov.ru`, `publication.pravo.gov.ru`, `actual.pravo.gov.ru:8000`.

## Остановка и перезапуск

```bash
docker compose stop                 # остановить всё, данные сохраняются
docker compose start                # запустить снова
docker compose restart bot          # перезапустить один сервис: bot, backend или postgres
docker compose logs -f --tail 200 bot   # логи бота и планировщика (backend, postgres — так же)
git pull && docker compose up -d --build   # обновить до новой версии; схема БД досоздаётся при старте
docker compose down                 # удалить контейнеры, данные в томе postgres_data остаются
docker compose down -v              # удалить контейнеры и базу
```

Все сервисы с `restart: unless-stopped` — после перезагрузки сервера поднимаются сами. Напоминания, пропущенные, пока бот лежал, отправляются при его старте.

## Ограничения

- **Один экземпляр бота на токен.** Бот получает сообщения long polling'ом: два запущенных экземпляра с одним `MAX_TOKEN` делят сообщения между собой. Не запускайте копию с боевым токеном, пока работает сервер.
- **Одну компанию ведёт один аккаунт MAX** — кто первым подключил ИНН. В рабочей версии владельца нужно подтверждать через Госуслуги (ЕСИА), на хакатоне это не сделано.
- **Режима налогообложения нет в открытых реестрах**, численность есть не у всех — их бот спрашивает одним нажатием, поправить можно в «Данных компании».
- **Источники ФНС — недокументированные эндпоинты сайтов** (реестр МСП, ЕГРЮЛ): могут не ответить или попросить капчу. Выписка ЕГРЮЛ грузится в фоне, ночная сверка идёт с паузами.
- **ЕРКНМ**: у ИП ИНН в открытых данных замаскирован, поэтому проверки ИП не находятся.
- **Законы**: тема акта определяется по названию, изменяемым актам и статьям НК/КоАП, а не по смыслу поправок (без LLM). Акты, вышедшие до подключения компании, не досылаются.
- **Документы** — черновики с реквизитами и памятки к отчётам; суммы налогов бот не считает.
- **Сроки** сверены с календарём бухгалтера на 2026 год; переносы выходных 2028 года — после постановления Правительства.
- **Мини-приложение открывается только внутри MAX**: вход подтверждается подписью `initData`. В обычном браузере — экран «Откройте приложение в MAX».
- **`DEBUG=true` на сервере** оставлен для показа: демо-команды доступны всем пользователям бота. После защиты — `DEBUG=false`.
- Схема БД меняется без Alembic: новые колонки досоздаёт список `NEW_COLUMNS` в `backend/databases/__init__.py`.

## Разработка без Docker

Python 3.12+, Node.js 20+, PostgreSQL.

```bash
pip install -r requirements.txt          # или uv sync
python backend/main.py                   # API на :8000; мини-приложение — из miniapp/build
python backend/bot/main_longpooling.py   # бот и планировщик
cd miniapp && npm ci && npm run build    # сборка мини-приложения; npm run dev — на моках, без бэкенда
```

`.env` читается из текущей папки; `DATABASE_URL` для локального PostgreSQL — `postgresql+asyncpg://max:max@localhost:5433/maxapp` (порт PostgreSQL из Docker). Демо-сроки поверх настоящих (просроченный, сегодняшний, выполненный): `python backend/seed_demo_tasks.py <ИНН>`, на сервере — `docker compose exec backend python backend/seed_demo_tasks.py <ИНН>`.

**Тесты:** `python -m unittest discover -s tests`. Сквозные тесты на PostgreSQL запускаются при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база` — схему они пересоздают; MAX и внешние сайты в них подменены.

**Зависимости** закреплены: `requirements.txt` (все пакеты с точными версиями, его ставит Dockerfile) выгружен из `uv.lock` командой `uv export --no-hashes --no-dev --no-emit-project -o requirements.txt`; мини-приложение — `miniapp/package-lock.json` (`npm ci`).

## Устройство

```text
backend/
├── main.py              FastAPI: API + статика мини-приложения
├── app/api/routes/      /api: session, company, dashboard, calendar, feed, tasks, settings, user/auth
├── bot/                 бот MAX: регистрация, вопросы профиля, кнопки пушей, демо-команды
├── notifications/       планировщик и очередь сообщений (worker.py), демо-тур (demo.py), модели радара
├── radar/               каталог обязанностей и сроки, детекторы изменений реестров, законы, шаблоны, документы
├── data_fetching/       клиенты реестра МСП, ЕГРЮЛ, ЕРКНМ, pravo.gov.ru
├── databases/           SQLAlchemy async, пользователи и компании
└── core/                настройки из окружения, проверка initData и JWT
miniapp/                 React + Vite + TypeScript, MAX Bridge
tests/                   unittest: каталог и сроки, документы, законы, детекторы, сквозные сценарии на PostgreSQL
```

Вход в мини-приложение: MAX передаёт подписанную строку `initData` → `POST /api/user/auth` проверяет HMAC-подпись токеном бота → JWT на 12 часов → остальные запросы с `Authorization: Bearer`. `user_id` из браузера не принимается.
