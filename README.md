# Радар обязанностей для малого бизнеса — бот и мини-приложение в MAX

## Назначение

**Для кого.** Владелец микро- или малого предприятия либо ИП без штатного юриста, который сам следит за налогами, отчётностью и проверками.

**Проблема.** О новых обязанностях и требованиях такой предприниматель узнаёт поздно и вслепую. Рассылки и новости пишутся для всех сразу, и каждый раз приходится разбираться, касается ли это его. Итог — часы на проверку или пропущенный срок и штраф.

**Что делает решение.** Пользователь присылает боту ИНН — и всё. Профиль компании собирается сам из официальных открытых данных: вид деятельности (ОКВЭД), категория МСП, численность, регион, лицензии — из реестра МСП ФНС; проверки и предостережения — из открытых данных ЕРКНМ. Дальше бот следит за изменениями и пишет **только то, что касается именно этой компании**:

- подходит срок обязанности: декларации, уведомления, взносы, отчёты — 20 обязанностей, сроки зависят от режима налогообложения, численности и типа компании;
- вышел закон или приказ, который касается компании: ежедневный разбор официального API publication.pravo.gov.ru, с объяснением «почему вам» и ссылкой на официальный текст;
- в ЕРКНМ появилась плановая проверка, профилактический визит или предостережение; компания исключена из реестра МСП или сменила категорию.

Бот не просто уведомляет: готовит черновик документа (.docx с реквизитами) и напоминает, пока задача не закрыта. Все источники данных — официальные: либо документированный API, либо государственные открытые данные; как именно и что в MVP подключено срезом — в разделе [«Внешние сервисы и интеграции»](#внешние-сервисы-и-интеграции).

## Основной пользовательский сценарий

ИНН в чате → «Нашли вашу компанию: … Всё верно?» → режим налогообложения одним нажатием (его нет в открытых реестрах) → «📡 Радар настроен: N обязанностей, ближайший срок …» → короткие напоминания в чат по одному, пока задача не закрыта → подробности, документ и отметка «Выполнено» — в мини-приложении.

| | Бот (чат MAX) | Мини-приложение |
|---|---|---|
| Регистрация | ИНН → карточка «Нашли вашу компанию» → «Всё верно?» → режим и численность кнопками → итог | Подключение по ИНН или QR-коду; «Данные компании» — поправить найденное в любой момент |
| Что-то случилось | Короткий пуш: что случилось и главная дата. Кнопки «📋 В список дел», «✅ Сделано», «🔕 Не актуально», «Открыть». Сообщения приходят по одному, отвеченное удаляется из чата | Экран события: почему вам, что сделать, куда сдавать, основание со ссылкой, штраф; «Подготовить документ», «Выполнено», «В список дел» |
| История и планы | В чате — только то, что ждёт решения | Главная («Сегодня», «На неделе», «Список дел»), календарь, лента всего, что писал бот |
| Настройки | `/profile` — карточка компании | «Данные компании», «Уведомления» (когда напоминать, тихие часы), тема |

## Состав и архитектура

| Компонент | Технологии | Что делает |
|---|---|---|
| Бот (`backend/bot`, контейнер `max_bot`) | Python 3.12, maxapi (MAX Bot API, long polling) | Регистрация по ИНН, вопросы профиля, пуши с кнопками, демо-команды |
| Планировщик (`backend/notifications/worker.py`, в процессе бота) | APScheduler | Напоминания в 09:00, очередь сообщений раз в минуту, ночная сверка ЕРКНМ, ежемесячная — реестра МСП, законы в 07:00 |
| Правила (`backend/radar`) | Python, Jinja2, python-docx | Каталог 20 обязанностей и расчёт сроков с переносом выходных, детекторы изменений реестров, разбор законов, тексты сообщений, документы |
| API мини-приложения (`backend/app`, контейнер `max_backend`) | FastAPI, SQLAlchemy async | REST `/api/...`, проверка подписи MAX, раздача собранного мини-приложения |
| Мини-приложение (`miniapp`) | React 19, TypeScript, Vite, MAX Bridge | Главная, календарь, экран события, лента, «Данные компании», настройки |
| База (контейнер `max_postgres`) | PostgreSQL 17, миграции Alembic (`backend/migrations`) | Реестр МСП из открытых данных, пользователи, компании, профили, события и сроки, очередь сообщений, разобранные законы |

```text
Пользователь MAX ──чат──► MAX Bot API ◄──long polling── max_bot (бот + планировщик) ──┐
       │                                                                               ├──► max_postgres
       └──мини-приложение (HTTPS)──► Caddy ──► max_backend (API /api + статика) ──────┘
max_bot ──► открытые данные ФНС (реестр МСП) и ЕРКНМ, API publication.pravo.gov.ru
```

Вход в мини-приложение: MAX передаёт подписанную строку `initData` → `POST /api/user/auth` проверяет HMAC-подпись токеном бота → JWT на 12 часов → остальные запросы с `Authorization: Bearer`. `user_id` из браузера не принимается. Структура кода:

```text
backend/
├── main.py              FastAPI: API + статика мини-приложения
├── app/api/routes/      /api: user, session, company, dashboard, calendar, feed, tasks, settings
├── bot/                 бот MAX
├── notifications/       планировщик и очередь сообщений, демо-тур, модели радара
├── radar/               обязанности и сроки, детекторы реестров, законы, шаблоны, документы
├── data_fetching/       открытые данные реестра МСП и ЕРКНМ, API pravo.gov.ru
├── data/                срез реестра МСП (официальный формат ФНС)
├── databases/           модели и запуск миграций при старте
├── migrations/          миграции Alembic
└── core/                настройки, проверка ИНН, подпись initData и JWT
miniapp/                 мини-приложение
tests/                   unittest, в том числе сквозные сценарии на PostgreSQL
```

## Запуск

Нужны Docker с Compose v2 и токен бота MAX (его выдают организаторы хакатона). Для работы внутри MAX мини-приложение должно быть доступно по HTTPS и привязано к боту (привязку делают организаторы по ссылке — FAQ хакатона, п. 2).

```bash
git clone https://github.com/y3llowman/webapp_max_fastapi.git
cd webapp_max_fastapi
cp .env.example .env    # вписать MAX_TOKEN, SECRET_KEY (openssl rand -hex 32), POSTGRES_PASSWORD (openssl rand -hex 16)
docker compose up -d --build
```

Одна команда поднимает все три компонента. Сборка с нуля без кэша — 75 с при обычной сети (замер 29.09, без загрузки базовых образов). Почти всё время уходит на загрузку пакетов npm и PyPI: при медленном доступе к registry.npmjs.org ночью 29.09 та же сборка шла 290 с, из них 270 с — `npm ci`. Без `MAX_TOKEN`, `SECRET_KEY` или `POSTGRES_PASSWORD` Compose остановится с сообщением, какой переменной не хватает. Схема БД создаётся и обновляется миграциями при старте API; бот стартует, когда API ответил на `/health`. При первом старте API загружает в базу срез реестра МСП из `backend/data/msp_slice.xml`, а бот 5–10 минут загружает акты pravo.gov.ru за 30 дней (в логе `pravo.gov.ru: N new acts about business`).

Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok"}`; `docker compose ps` — `max_backend` в статусе `healthy`, `max_bot` — `Up`.

**HTTPS.** Порт 8000 открыт только на 127.0.0.1, снаружи API и мини-приложение отдаёт обратный прокси с сертификатом. На сервере это Caddy (`/etc/caddy/Caddyfile`):

```
hackaton267max.webtm.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Если бот другой, перед сборкой поменяйте его ник в `miniapp/.env.production` (`VITE_MAX_BOT_NAME` — кнопка «В чат MAX»).

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `MAX_TOKEN` | да | Токен бота MAX. Им бот получает сообщения и пишет в чат, а API проверяет подпись `initData` мини-приложения |
| `SECRET_KEY` | да | Ключ подписи сессий мини-приложения, не короче 32 символов: `openssl rand -hex 32` |
| `POSTGRES_PASSWORD` | да | Пароль базы (только латиница и цифры — он входит в URL подключения): `openssl rand -hex 16`. Применяется при первом создании тома базы; сменить потом — `ALTER USER max PASSWORD '…'` в базе и новое значение в `.env` |
| `APP_URL` | нет | HTTPS-адрес мини-приложения, привязанный к боту. Код его не читает: мини-приложение и API отдаёт один контейнер, запросы идут на относительный `/api` |
| `DEMO` | нет, по умолчанию `true` | Демо-команды бота: `/demo`, `/demo_remind`, `/demo_event`, `/demo_law`, `/laws` |
| `MSP_FULL_REFRESH` | нет, по умолчанию `false` | `true` — 11-го числа каждого месяца бот сам скачивает свежий полный набор реестра МСП (архив ~2,1 ГБ, ~6,8 млн записей) по паспорту набора и заменяет им срез. Нужно ~5 ГБ свободного места. Вручную: `docker compose exec bot python backend/load_msp_registry.py --full` |
| `LAW_PDF` | нет, по умолчанию `false` | `true` — вместе с сообщением о законе бот присылает PDF официального текста. Выключено: см. [ограничения](#известные-ограничения) |
| `DEBUG` | нет, по умолчанию `false` | `true` — подробные логи API и трассировки ошибок в ответах. На сервере не включать |
| `MAX_INIT_DATA_MAX_AGE` | нет, по умолчанию `86400` | Сколько секунд подпись мини-приложения от MAX считается свежей |
| `DATABASE_URL` | только без Docker | В Docker собирается в `compose.yaml`. Для запуска без Docker: `postgresql+asyncpg://max:<пароль>@localhost:5433/maxapp` |

## Порты

| Порт на хосте | Контейнер | Что там |
|---|---|---|
| `127.0.0.1:8000` | `max_backend:8000` | Мини-приложение (`/`), API (`/api/...`), `/health`, Swagger (`/docs`), `openapi.json` (`/openapi.json`) |
| `127.0.0.1:5433` | `max_postgres:5432` | PostgreSQL, пользователь `max`, база `maxapp` |

Оба порта слушают только локальный интерфейс; наружу — через HTTPS-прокси. Боту входящие порты не нужны.

## Зависимости

- Python: [`requirements.txt`](requirements.txt) — все пакеты с точными версиями, его ставит Dockerfile. Выгружен из `uv.lock` командой `uv export --no-hashes --no-dev --no-emit-project -o requirements.txt`; прямые зависимости закреплены и в `pyproject.toml`.
- Мини-приложение: [`miniapp/package-lock.json`](miniapp/package-lock.json), ставится через `npm ci`.
- Базовые образы: `node:20` (сборка мини-приложения), `python:3.12-slim`, `postgres:17-alpine`. Приложение в контейнере работает не от root.

## Внешние сервисы и интеграции

Бот обращается только к документированным API и к государственным открытым данным. Внутри Docker эти сервисы воспроизвести нельзя: нужен выход в интернет.

| Сервис | Зачем | Как получаем | Основание |
|---|---|---|---|
| MAX Bot API (`platform-api2.max.ru`) | Сообщения бота, кнопки, файлы | Библиотека maxapi, long polling | [Документация API MAX](https://dev.max.ru/docs-api) |
| MAX Bridge (`st.max.ru/js/max-web-app.js`) | Вход в мини-приложение, QR-сканер, кнопка «Назад», ссылки | Скрипт в `miniapp/index.html` | [Документация MAX Bridge](https://dev.max.ru/docs/webapps/bridge) |
| Реестр МСП ФНС — открытые данные | Профиль по ИНН: название, ОГРН, ОКВЭД, категория, численность, регион, лицензии; ежемесячная сверка (исключение, смена категории) | Набор `7707329152-rsmp` (XML, схема XSD, раз в месяц 10-го). Ссылку на свежий архив берём из паспорта набора `meta.csv`, записи — в таблицу `msp_registry`, поиск по ИНН — в своей базе. **В MVP загружен срез** — 10 компаний из набора на 10.09.2026 | [Набор на nalog.gov.ru](https://www.nalog.gov.ru/opendata/7707329152-rsmp/) |
| ЕРКНМ — открытые данные Генпрокуратуры | Плановые проверки, профилактические визиты, предостережения по ИНН | Месячные наборы `7710146102-inspection-<год>-<месяц>`: паспорт `meta.xml` по методическим рекомендациям 3.0 → ссылка на архив XML → поиск по ИНН | Паспорт набора на proverki.gov.ru |
| Официальное опубликование (`publication.pravo.gov.ru`) | Новые законы и приказы | Только методы из документации: `/api/Documents` (список актов за день, поиск изменяемого акта по номеру и дате) | [publication.pravo.gov.ru/help](http://publication.pravo.gov.ru/help) |

**Чего в MVP нет и почему.**

- **ЕГРЮЛ** (КПП, адрес, руководитель, недостоверность, дисквалификация, ликвидация, смена руководителя). Бесплатного документированного API у ФНС нет: сервис выписок egrul.nalog.ru рассчитан на людей, а для информационных систем ФНС предоставляет отдельный доступ (ниже). Поэтому реквизиты для документов пользователь вписывает сам в «Данных компании», а события ЕГРЮЛ показываются только в `/demo` — как имитация с пометкой.
- **Текст закона и PDF.** В документации pravo.gov.ru нет метода, который отдаёт текст акта, а полнотекстовый поиск (параметр `DocumentText`) на 29.09.2026 возвращает 0 результатов. Поэтому тема акта определяется по названию и по названию изменяемого акта, дата вступления в силу не извлекается, а вместо файла бот даёт кнопку со ссылкой на официальную страницу акта. Скачивание PDF по ссылке сайта реализовано, но выключено (`LAW_PDF=false`): мы не уверены, что эта ссылка допустима как API.

## Работа с данными

- **Что храним** (PostgreSQL): реестр МСП из открытых данных ФНС (`msp_registry`, в MVP — срез) и журнал его загрузок; пользователь MAX (id, имя, username, фото, язык, настройки уведомлений); подключённая компания и снимок её записи в реестре МСП — для сравнения при ежемесячной сверке; ответы пользователя о режиме, численности, поправки к реестру и реквизиты для документов (КПП, адрес, руководитель); события и сроки; очередь и история сообщений бота; разобранные законы.
- **Откуда.** Факты — из открытых данных ФНС и ЕРКНМ и из API pravo.gov.ru; в сообщениях указан источник и дата данных («реестр МСП, срез открытых данных ФНС на 10.09.2026»). Сроки и «почему вам» — расчёт бота по правилам из `backend/radar/obligations.py` со ссылкой на статью. Режим налогообложения и численность (если её нет в реестре) — ответ пользователя, помечается «указан вами».
- **Доступ.** Мини-приложение видит только компанию своего пользователя: вход по подписи MAX, JWT на 12 часов, каждый запрос проверяет, что событие принадлежит его компании. Одну компанию ведёт один аккаунт MAX. Секреты — только в `.env`, в репозитории их нет. База доступна только с самого сервера.
- **Сколько.** Лента в мини-приложении показывает 90 дней; сроки создаются на 365 дней вперёд. Автоматического удаления старых данных в MVP нет.
- **Схема** меняется миграциями Alembic (`backend/migrations`); при старте API база обновляется до последней ревизии.

## Тестовые данные

- **Срез реестра МСП** — [`backend/data/msp_slice.xml`](backend/data/msp_slice.xml): 10 записей из официального набора ФНС на 10.09.2026 в исходном формате, без изменений. При первом старте API загружает его в таблицу `msp_registry`; в сообщениях и в приложении источник подписан «срез открытых данных ФНС». ИНН не из среза бот не подключает и честно говорит, что его нет в срезе, а не «нет в реестре». Пересобрать срез из скачанного архива набора: `python backend/load_msp_registry.py --zip <архив.zip> --make-slice --inn <ИНН> …`; загрузить весь набор вместо среза: `python backend/load_msp_registry.py --full`. Ожидаемые ответы по ИНН — в [`test-data.json`](test-data.json).
- **Имитации в `/demo` и `/demo_event`.** Настоящего события в реестре у демо-компании нет, поэтому тур показывает события реестров (проверка в ЕРКНМ, недостоверность, дисквалификация, исключение из реестра МСП и т. д.) на подставных выписках. Их строят те же детекторы, что и ночные сверки. В базе у таких событий `source = "demo"`, на экране события — «Имитация для демо», кнопка «🧹 Убрать демо-события» удаляет их. Сроки обязанностей, документы и законы в туре — настоящие.
- **Демо-сроки.** `docker compose exec backend python backend/seed_demo_tasks.py <ИНН>` добавляет просроченную, сегодняшнюю и выполненную задачу (помечены как демо), чтобы показать все статусы.

## Собственный API

HTTP-методы бэкенда — часть продукта: через них работает мини-приложение.

| Что | Где |
|---|---|
| Адрес | `https://hackaton267max.webtm.ru/api` (и `https://hackaton267max.webtm.ru/health`) |
| OpenAPI 3.1 | [`openapi.json`](openapi.json), Swagger UI — https://hackaton267max.webtm.ru/docs. Файл выгружается из кода: `python backend/export_openapi.py`; тест `tests/test_openapi.py` падает, если он устарел |
| Проверки | [`DATA-API.yaml`](DATA-API.yaml): 23 проверки — метод, путь, параметры, роль, ожидаемые коды и обязательные поля ответа |
| Тестовые данные | [`test-data.json`](test-data.json) |
| Тестовая учётная запись | Пользователь MAX `9000000000000000001` (роль `user`). Паролей в API нет: вход — по `initData`, подписанному токеном бота, как это делает клиент MAX |

Получить токен для проверки:

```bash
MAX_TOKEN=<токен бота> python backend/sign_init_data.py > init_data.txt
curl -s -X POST https://hackaton267max.webtm.ru/api/user/auth \
     -H "Content-Type: application/json" \
     -d "{\"initData\": \"$(cat init_data.txt)\"}"
# {"access_token":"eyJ…","token_type":"bearer"}
curl -s https://hackaton267max.webtm.ru/api/user/me -H "Authorization: Bearer eyJ…"
```

Скрипту нужен только Python и пакет `python-dotenv`. Подпись действует 24 часа, токен — 12 часов. Коды ответов: 401 — нет токена или подпись неверна, 404 — компания не подключена или событие не найдено, 409 — компанию ведёт другой пользователь, 422 — неверные данные (ИНН с ошибкой в контрольной сумме, неизвестный режим, КПП не из 9 цифр и т. п.). Для ИНН не из среза `POST /api/session` отвечает 404 с `detail` «INN not found in the SME registry slice loaded in this MVP». `POST /api/tasks/{id}/document` у тестового пользователя возвращает 502: MAX не может отправить файл несуществующему аккаунту.

## Возможности MAX

- Мини-приложение привязано к боту: кнопки `open_app` в сообщениях открывают его сразу на нужном экране (диплинк `startapp=task_<id>` — экран события из пуша, `profile_edit` — «Данные компании»).
- Сканер QR-кода клиента MAX (`openCodeReader`) — ИНН можно не вводить, а отсканировать.
- Системная кнопка «Назад», тактильный отклик, открытие внешних ссылок и чата с ботом через MAX Bridge; тема оформления как в MAX.
- Бот удаляет сообщения, на которые уже ответили, и присылает следующее по одному — в чате только то, что ждёт решения.
- Файлы в чат — черновики документов .docx; кнопки-ссылки под сообщением о законе ведут на официальный текст.

## Известные ограничения

- **Один экземпляр бота на токен.** Бот получает сообщения long polling'ом: два запущенных экземпляра с одним `MAX_TOKEN` делят сообщения между собой. Не запускайте копию с боевым токеном, пока работает сервер.
- **Одну компанию ведёт один аккаунт MAX** — кто первым подключил ИНН. В рабочей версии владельца нужно подтверждать через Госуслуги (ЕСИА).
- **Режима налогообложения нет в открытых реестрах**, численность есть не у всех — их бот спрашивает одним нажатием.
- **Реестр МСП в MVP — срез из 10 компаний** официального набора на 10.09.2026. Полная ежемесячная загрузка реализована и включается `MSP_FULL_REFRESH=true`, но на демо-сервере выключена: ~5 ГБ диска ради проверки не нужны.
- **ЕГРЮЛ не подключён** — бесплатного документированного API нет (см. [интеграции](#внешние-сервисы-и-интеграции)). Реквизиты для документов пользователь вписывает сам; события ЕГРЮЛ — только имитация в `/demo`.
- **Законы — без текста**: тема — по названию и изменяемому акту, дата вступления в силу не определяется, PDF не прикладывается (`LAW_PDF=false`).
- **ЕРКНМ**: у ИП ИНН в открытых данных замаскирован, поэтому проверки ИП не находятся.
- **Законы**: тема акта определяется по названию, изменяемым актам и статьям НК/КоАП, а не по смыслу поправок (без LLM). Акты, вышедшие до подключения компании, не досылаются.
- **Документы** — черновики с реквизитами и памятки к отчётам; суммы налогов бот не считает.
- **Сроки** сверены с календарём бухгалтера на 2026 год; переносы выходных 2028 года — после постановления Правительства.
- **Мини-приложение открывается только внутри MAX**: вход подтверждается подписью `initData`. В обычном браузере — экран «Откройте приложение в MAX».
- **Демо-команды** (`DEMO=true`) доступны всем пользователям бота — оставлены для проверки жюри.

## Остановка и повторный запуск

```bash
docker compose stop                       # остановить всё, данные сохраняются
docker compose start                      # запустить снова
docker compose restart bot                # перезапустить один сервис: bot, backend или postgres
docker compose logs -f --tail 200 bot     # логи бота и планировщика (backend, postgres — так же)
git pull && docker compose up -d --build  # обновить до новой версии; миграции применятся при старте
docker compose down                       # удалить контейнеры, база в томе postgres_data остаётся
docker compose down -v                    # удалить контейнеры и базу
```

Все сервисы с `restart: unless-stopped` — после перезагрузки сервера поднимаются сами. Напоминания, пропущенные, пока бот лежал, отправляются при его старте. Логи контейнеров ограничены: 5 файлов по 10 МБ.

## Разработка без Docker

Python 3.12+, Node.js 20+, PostgreSQL.

```bash
pip install -r requirements.txt           # или uv sync
python backend/main.py                    # API на :8000; мини-приложение — из miniapp/build
python backend/bot/main_longpooling.py    # бот и планировщик
cd miniapp && npm ci && npm run build     # сборка мини-приложения; npm run dev — на моках, без бэкенда
```

`.env` читается из текущей папки. Новая миграция после изменения моделей: `cd backend && alembic revision --autogenerate -m "<что изменилось>"` (нужны `DATABASE_URL` и `MAX_TOKEN`).

**Тесты:** `python -m unittest discover -s tests`. Сквозные тесты на PostgreSQL запускаются при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база` — схему они пересоздают; MAX и внешние сайты в них подменены.

Подробное текущее состояние — источники данных, расписание, все функции, допущения и TODO — в [CURRENT_STATE.md](CURRENT_STATE.md).
