# Текущее состояние проекта

_Обновлено: 30.09.2026, ночь перед сдачей._ Идея продукта и правила работы — [CLAUDE.md](CLAUDE.md), описание для жюри и запуск — [README.md](README.md).

**Одной строкой.** ИНН в чате MAX → профиль компании из официальных открытых данных ФНС → список обязанностей со сроками только для этой компании → короткие пуши по одному до закрытия задачи → подробности и документ в мини-приложении. Каждый день — новые законы через API pravo.gov.ru, каждую ночь — проверки ЕРКНМ. Сквозной сценарий проверен тестами на PostgreSQL (108 тестов).

**Состояние данных (важно).** Реестр МСП — срез из 10 настоящих компаний (`backend/data/msp_slice.xml`, набор ФНС на 10.09.2026); полная загрузка реализована (`MSP_FULL_REFRESH`), на демо-сервере выключена. ЕГРЮЛ не подключён: события — только имитация в `/demo`, реквизиты вводит пользователь. Законы — без текста акта, вместо PDF ссылка (`LAW_PDF=false`). Причины и стоимость продакшн-каналов — в README.

## Сервер и команды

`https://hackaton267max.webtm.ru` — сервер 72.56.0.157, проект в `/opt/webapp_max_fastapi`, обратный прокси Caddy → `127.0.0.1:8000`. Секреты — только в `.env` на сервере.

| Что | Команда на сервере |
|---|---|
| Выложить версию | `cd /opt/webapp_max_fastapi && git pull && docker compose up -d --build`; затем `docker compose ps` (`max_backend` — `healthy`, `max_bot` — `Up`) |
| Если БД не принимает пароль из `.env` | Том БД создан со старым паролем `max`. `docker compose exec postgres psql -U max -d maxapp -c "ALTER USER max PASSWORD '<POSTGRES_PASSWORD из .env>'"`, потом `docker compose up -d` |
| Логи | `docker logs -f --tail 200 max_bot` (бот, планировщик), `max_backend` (API), `max_postgres`; `journalctl -u caddy -f` |
| Очередь сообщений | `docker compose exec postgres psql -U max -d maxapp -c "select id, label, status, scheduled_at, error from notifications order by id desc limit 20"` |
| Что загружено из реестра МСП | `docker compose exec postgres psql -U max -d maxapp -c "select * from msp_registry_loads order by id desc limit 3"` |
| Освободить ИНН среза | команда в README, раздел «Тестовые данные» |

Локально с боевым `MAX_TOKEN` бота не запускать: два экземпляра делят сообщения между собой.

## Ключевые правила

- **Одна компания — один аккаунт MAX.** Второй получает отказ. Новая компания отвязывает прежнюю и отменяет её напоминания.
- **Хранятся только поправки пользователя**, совпадающее с реестром не хранится; поправка важнее реестра.
- **Очередь по одному:** пока на пуш не ответили, следующий не приходит (не дольше суток). Отвеченное удаляется из чата, история — в ленте приложения.
- **Компании не из среза** не подключаются, а сверка их пропускает; «нет в реестре» показывается только при полной загрузке.
- **Схема БД** меняется только миграциями. `users.max_user_id` — bigint.
- **Комментариев и докстрингов в коде нет** по решению команды; объяснения — здесь и в README.

## Допущения

- Сроки и штрафы сверены с календарём бухгалтера на 2026 год; при изменении НК сверять заново. Стоит показать бухгалтеру: АУСН с сотрудниками (НДФЛ считает банк), КБК аванса НДФЛ ИП (зависит от суммы дохода), сроки оплаты патента от даты, которую указал пользователь.
- Сроки создаются от сегодняшнего дня вперёд: прошлые не создаются, чтобы не пугать просрочками при подключении.
- Число обязанностей в «Радаре настроен» зависит от даты: для `7743212897` на 30.09.2026 — 10.
- Клиент MAX внедряет в мини-приложение скрипт, который при повторном внедрении зацикливается; `index.html` до всех скриптов закрепляет штатную функцию.
- Поведение уже открытого приложения при новом «Открыть» из чата зависит от клиента MAX: приложение ловит смену адреса, а «В чат MAX» закрывает приложение. В живом MAX не проверялось.
- Код ошибки MAX при блокировке бота в документации не описан; бот считает заблокировавшим 403 и 404 (`worker._send`).
