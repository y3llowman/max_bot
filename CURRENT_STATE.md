**Одной строкой:** ИНН → профиль из реестра МСП, ЕГРЮЛ и ЕРКНМ плюс один-два вопроса кнопками → список обязанностей со сроками только для этой компании → напоминания в чат MAX до закрытия задачи → черновик документа в чат. Всё это работает сквозным сценарием. Проверено тестами на PostgreSQL, в живом MAX не прогонялось.

## Как запустить

| Что | Команда |
|---|---|
| Всё в Docker | `docker compose up --build`: postgres, API на :8000 (отдаёт и собранное мини-приложение), бот вместе с планировщиком |
| API локально | из корня: `python backend/main.py` (`.env` читается из текущей папки; `DATABASE_URL` на localhost:5433). Статику берёт из `miniapp/build` — сначала `npm run build` в `miniapp/` |
| Бот локально | из корня: `python backend/bot/main_longpooling.py` |
| Мини-приложение | `cd miniapp && npm run dev`. Без `VITE_API_URL` работает на моках, подробности — [miniapp/README.md](miniapp/README.md) |
| Тесты | `python -m unittest discover -s tests`. Тесты с БД запускаются только при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база`: схему они пересоздают. Без Docker подойдёт локальный PostgreSQL: `initdb -D <папка> -U max -A trust`, `pg_ctl -D <папка> -o "-p 5544" start`, `createdb -p 5544 -U max maxtest` |

Демо-сроки поверх настоящих: `python backend/seed_demo_tasks.py <ИНН>`. Добавляют просроченную и выполненную задачи.

### Сервер

`https://hackaton267max.webtm.ru` — сервер 72.56.0.157 (`ssh root@72.56.0.157`). По голому IP HTTPS не работает: сертификат выписан на домен. Caddy (`/etc/caddy/Caddyfile`, сервис systemd) принимает HTTPS и проксирует на `127.0.0.1:8000`. Проект запущен через `docker compose`. Порты postgres (5433) и API (8000) открыты только на 127.0.0.1: пароль базы лежит в `docker-compose.yml`, а API снаружи доступен только через Caddy.

## Сквозной сценарий

1. **ИНН.** В боте — `/start` или просто 10/12 цифр в любой момент. В мини-приложении — экран «Подключение». Проверяется контрольная сумма, данные берутся из реестра МСП.
2. **Профиль.** Из реестра МСП: название, ОКВЭД, категория, регион, лицензии и среднесписочная численность (`od2_sschr`, есть не у всех). Из ЕГРЮЛ (PDF, в фоне): КПП, адрес, директор — для документов. Режима налогообложения в открытых реестрах нет — бот спрашивает его кнопками. О численности спрашивает, только если её нет в реестре. Мини-приложение, пока ответов нет, показывает плашку «Ответьте на вопросы в чате».
3. **Обязанности.** `materialize_for` берёт из каталога 15 обязанностей только применимые и записывает сроки на год вперёд. Срок, выпавший на выходной, переносится на рабочий день (праздники и переносы 2026 и 2027 годов). Меняется профиль — меняется список; бот сообщает, что добавилось и что ушло. В итоге онбординга и в профиле мини-приложения — льготы, доступные при численности компании.
4. **Напоминания.** В 09:00 МСК — по настройке пользователя (по умолчанию за 30, 7 и 1 день и в день срока). После срока — каждый день, пока задачу не закроют. Сроки на одну дату приходят одним сообщением. Кнопки под сообщением: «Сделано», «Завтра», «Не актуально», «Подготовить документ», «Открыть» (экран задачи в мини-приложении).
5. **Документ.** Черновик .docx с реквизитами бот присылает в чат — из мини-приложения или кнопкой под напоминанием.
6. **События реестров.** Проверяются ночью, сразу после ввода ИНН и по кнопке «Просканировать сейчас» (МСП — сразу, ЕГРЮЛ и ЕРКНМ — в фоне, находки приходят в чат).
   - **Реестр МСП** (раз в месяц): исключение, отсутствие в реестре, смена категории (при выходе из микропредприятий появляется задача по ЛНА).
   - **ЕГРЮЛ, состояния** (держатся, пока видны в выписке; исчезли — событие закрывается): отметка о недостоверности → задача со сроком «через 6 месяцев после записи ФНС может исключить»; дисквалификация руководителя; ликвидация, реорганизация или предстоящее исключение → при исключении задача «возражение Р38001» со сроком 3 месяца от записи.
   - **ЕГРЮЛ, изменения** между двумя снимками: руководитель, участники, адрес, налоговая инспекция. Новый руководитель-иностранец → ещё и задача «уведомить МВД».
   - **ЕГРЮЛ, снятие**: отметка о недостоверности исчезла → «отметка снята»; дисквалификация закончилась по сроку → «срок истёк».
   - **ЕРКНМ** (proverki.gov.ru, открытые данные): проверка или профилактический визит по ИНН → задача со сроком = дата начала; объявленное предостережение → сообщение; отменённое мероприятие → задача скрывается.

## Мини-приложение (`miniapp/`)

React + Vite, экраны по макетам. Контракт — `src/api/types.ts`, моки — `src/api/mock.ts`.

- **Дашборд:** карточка радара — когда проверяли реестры и кнопка «Просканировать сейчас». Во время проверки крутится луч радара (`components/RadarScan.tsx`), потом дашборд перезагружается. Плашка «Ответьте на вопросы в чате», пока профиль неполный. Точка на колокольчике — есть сообщения бота, которые пользователь ещё не видел.
- **Задача:** чип периодичности, раскрытые «Почему вам» и «Риски», ссылки «Открыть сайт» и «Открыть текст закона» (открываются через `WebApp.openLink`). Кнопки: «Выполнено» и «Подготовить документ» — вторая только у задач с черновиком.
- **Профиль:** ОКВЭД, категория, численность, регион, ИНН, КПП, ОГРН; блок «Доступно при вашей численности» со ссылками на нормы. Строки «Контрагенты» больше нет.
- **Уведомления:** режим «За 30, 7 и 1 день» (по умолчанию). Открытие экрана гасит точку на колокольчике.
- `npm run build` и `tsc` проходят. Дашборд, сканирование, профиль, задача и уведомления просмотрены на моках в светлой и тёмной темах (скриншоты Playwright, 390 px).

## Демо на защите

1. Пришлите боту ИНН → карточка → ответьте на вопросы → список обязанностей, ближайшие сроки и льготы по численности.
2. «Открыть ленту обязанностей» → «Просканировать сейчас» → задача → «Почему вам», «Подготовить документ» → файл в чате.
3. `/demo_remind` — напоминания по трём ближайшим срокам сразу. Под сообщением — «Сделано» / «Завтра».
4. `/demo_event msp_excluded` — «исключены из реестра МСП». `/demo_event knm` — проверка из ЕРКНМ: настоящие данные ЕРКНМ подключены, но у демо-компании проверок, скорее всего, нет — поэтому команда имитирует запись (так и сказать).
5. `/profile` → сменить численность → бот пишет, какие обязанности появились или ушли.

## Допущения, которые стоит знать

- Сроки и штрафы сверены с календарём бухгалтера на 2026 год. Если меняется НК — сверять заново. В каждом напоминании есть оговорка «сверяйтесь с календарём ФНС».
- Сроки создаются от сегодняшнего дня вперёд. Прошлые не создаются, чтобы при подключении не пугать просрочками, которые, скорее всего, уже закрыты.
- Численность: ответ пользователя (в `/profile`) важнее реестра МСП — реестр отстаёт на год. Нет данных в реестре → бот спрашивает диапазоном.
- События реестров со сроком (недостоверность, исключение, МВД, проверки) приходят сразу отдельным сообщением, а напоминания по ним начинаются со следующего дня — чтобы не было двух сообщений подряд. Если 6 месяцев с отметки о недостоверности уже прошли, задача сразу просрочена и напоминает каждый день: исключить компанию могут в любой момент.
- Изменение адреса бывает и без участия компании — при переименовании улицы. Сообщение об этом предупреждает.
- ЕРКНМ: мероприятие, которое уже началось, в задачи не попадает — о нём компания уже знает.
- Задачу, которая перестала касаться компании, удаляем вместе с её будущими сроками. Отметку «Не актуально» пользователя пересчёт профиля не трогает.
- Отправка в MAX не проверена вживую: MAX может не дать написать пользователю, который ни разу не запускал бота. Тогда документ из мини-приложения вернёт 502 и тост «Не получилось». Кнопка `open_app` передаёт `web_app` (username бота) и `contact_id`; ошибку 400 на выборе численности это исправило, открытие мини-приложения по кнопке — проверить в клиенте MAX.
