# Текущее состояние проекта

_Обновлено: 27.09.2026. Идея продукта и правила работы — в [CLAUDE.md](CLAUDE.md). Исходный план и его ревизия — в [TODO.md](TODO.md)._

**Одной строкой:** ИНН → профиль из реестра МСП и ЕГРЮЛ плюс два вопроса кнопками → список обязанностей со сроками только для этой компании → напоминания в чат MAX до закрытия задачи → черновик документа в чат. Всё это работает сквозным сценарием. Проверено тестами на PostgreSQL, в живом MAX не прогонялось.

## Как запустить

| Что | Команда |
|---|---|
| Всё в Docker | `docker compose up --build`: postgres, API на :8000 (отдаёт и собранное мини-приложение), бот вместе с планировщиком |
| API локально | из корня: `python backend/main.py` (`.env` читается из текущей папки; `DATABASE_URL` на localhost:5433) |
| Бот локально | из корня: `python backend/bot/main_longpooling.py` |
| Мини-приложение | `cd frontend && npm run dev`. Без `VITE_API_URL` работает на моках, подробности — [frontend/README.md](frontend/README.md) |
| Тесты | `python -m unittest discover -s tests`. Тесты с БД запускаются только при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база`: схему они пересоздают |

Демо-сроки поверх настоящих: `python backend/seed_demo_tasks.py <ИНН>`. Добавляют просроченную и выполненную задачи.

## Сквозной сценарий

1. **ИНН.** В боте — `/start` или просто 10/12 цифр в любой момент. В мини-приложении — экран «Подключение». Проверяется контрольная сумма, данные берутся из реестра МСП.
2. **Профиль.** Из реестра МСП: название, ОКВЭД, категория, регион, лицензии. Из ЕГРЮЛ (PDF, в фоне): КПП, адрес, директор — для документов. Режима налогообложения и численности в открытых реестрах нет, поэтому бот спрашивает их двумя вопросами кнопками. Мини-приложение, пока ответов нет, показывает плашку «Ответьте на 2 вопроса в чате».
3. **Обязанности.** `materialize_for` берёт из каталога 15 обязанностей только применимые и записывает сроки на год вперёд. Срок, выпавший на выходной, переносится на рабочий день. Меняется профиль — меняется список; бот сообщает, что добавилось и что ушло.
4. **Напоминания.** В 09:00 МСК — по настройке пользователя (по умолчанию за 30, 7 и 1 день и в день срока). После срока — каждый день, пока задачу не закроют. Сроки на одну дату приходят одним сообщением. Кнопки под сообщением: «Сделано», «Завтра», «Не актуально», «Подготовить документ», «Открыть» (экран задачи в мини-приложении).
5. **Документ.** Черновик .docx с реквизитами бот присылает в чат — из мини-приложения или кнопкой под напоминанием.
6. **События реестров.** Раз в месяц реестр МСП сверяется со снимком: исключение, отсутствие в реестре, смена категории (при выходе из микропредприятий появляется задача по ЛНА). ЕРКНМ — только имитация командой.

## Мини-приложение (`frontend/`)

React + Vite, экраны по макетам. Контракт — `src/api/types.ts`, моки — `src/api/mock.ts`.

- **Задача:** чип периодичности, раскрытые «Почему вам» и «Риски», ссылки «Открыть сайт» и «Открыть текст закона» (открываются через `WebApp.openLink`). Кнопки: «Выполнено» и «Подготовить документ» — вторая только у задач с черновиком.
- **Профиль:** ОКВЭД, категория, численность, регион, ИНН, КПП, ОГРН.
- **Дашборд:** плашка «Ответьте на 2 вопроса в чате», пока профиль неполный.
- **Уведомления:** добавлен режим «За 30, 7 и 1 день» (по умолчанию).
- `npm run build` и `tsc` проходят. Вёрстку новых элементов глазами не проверяли.

## Демо на защите

1. Пришлите боту ИНН → карточка → ответьте на 2 вопроса → список обязанностей и ближайшие сроки.
2. «Открыть ленту обязанностей» → задача → «Почему вам», «Подготовить документ» → файл в чате.
3. `/demo_remind` — напоминания по трём ближайшим срокам сразу. Под сообщением — «Сделано» / «Завтра».
4. `/demo_event msp_excluded` — «исключены из реестра МСП». `/demo_event knm` — проверка из ЕРКНМ (честно назвать имитацией).
5. `/profile` → сменить численность → бот пишет, какие обязанности появились или ушли.

## Допущения, которые стоит знать

- Сроки и штрафы сверены с календарём бухгалтера на 2026 год. Если меняется НК — сверять заново. В каждом напоминании есть оговорка «сверяйтесь с календарём ФНС».
- Сроки создаются от сегодняшнего дня вперёд. Прошлые не создаются, чтобы при подключении не пугать просрочками, которые, скорее всего, уже закрыты.
- Задачу, которая перестала касаться компании, удаляем вместе с её будущими сроками. Отметку «Не актуально» пользователя пересчёт профиля не трогает.
- Отправка в MAX не проверена вживую: MAX может не дать написать пользователю, который ни разу не запускал бота. Тогда документ из мини-приложения вернёт 502 и тост «Не получилось». Кнопка `open_app` использует `contact_id` бота — проверить в клиенте MAX.
