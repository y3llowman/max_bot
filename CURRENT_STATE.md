## Как запустить

| Что | Команда |
|---|---|
| Всё в Docker | `docker compose up --build`: postgres, API на :8000 (отдаёт и собранное мини-приложение), бот вместе с планировщиком |
| API локально | из корня: `python backend/main.py` (`.env` читается из текущей папки; `DATABASE_URL` на localhost:5433; без `SECRET_KEY` от 32 символов API не стартует). Статику берёт из `miniapp/build` — сначала `npm run build` в `miniapp/` |
| Бот локально | из корня: `python backend/bot/main_longpooling.py` |
| Мини-приложение | `cd miniapp && npm run dev`. Без `VITE_API_URL` работает на моках, подробности — [miniapp/README.md](miniapp/README.md) |
| Тесты | `python -m unittest discover -s tests`. Тесты с БД запускаются только при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база`: схему они пересоздают. Без Docker подойдёт локальный PostgreSQL: `initdb -D <папка> -U max -A trust`, `pg_ctl -D <папка> -o "-p 5544" start`, `createdb -p 5544 -U max maxtest` |

Демо-сроки поверх настоящих: `python backend/seed_demo_tasks.py <ИНН>` (на сервере: `docker compose exec backend python backend/seed_demo_tasks.py <ИНН>`). Добавляют просроченную, сегодняшнюю, ближайшие и выполненную задачи.

### Сервер

`https://hackaton267max.webtm.ru` — сервер 72.56.0.157 (`ssh root@72.56.0.157`), проект в `/opt/webapp_max_fastapi`. По голому IP HTTPS не работает: сертификат выписан на домен. Caddy (`/etc/caddy/Caddyfile`, сервис systemd) принимает HTTPS и проксирует на `127.0.0.1:8000`. Проект запущен через `docker compose`. Порты postgres (5433) и API (8000) открыты только на 127.0.0.1: пароль базы лежит в `docker-compose.yml`, а API снаружи доступен только через Caddy.

| Что | Команда на сервере |
|---|---|
| Выложить новую версию | `cd /opt/webapp_max_fastapi && git pull && docker compose up -d --build`. Новые таблицы и колонки досоздаются при старте, миграции вручную не нужны. **С версии 28.09 (вечер) в `.env` сервера обязателен `SECRET_KEY`** (`openssl rand -hex 32`), иначе `max_backend` не стартует |
| Законы с pravo.gov.ru | После первого старта бот 5–10 минут загружает акты за 30 дней (без рассылки): `docker logs max_bot \| grep pravo`. Что разобрано: `docker compose exec postgres psql -U max -d maxapp -c "select published, topics, region, left(name, 80) from laws where topics <> '[]' order by published desc limit 20"` |
| Логи | `docker logs -f --tail 200 max_bot` (бот и планировщик), `max_backend` (API мини-приложения), `max_postgres`; `journalctl -u caddy -f` (HTTPS) |
| Что запущено | `docker ps` |
| Очередь сообщений | `docker compose exec postgres psql -U max -d maxapp -c "select id, label, status, scheduled_at, error from notifications order by id desc limit 20"` |

Локально бот с боевым `MAX_TOKEN` не запускать: два экземпляра делят между собой входящие сообщения.

## Откуда берутся данные

Все внешние источники — бесплатные открытые сервисы без ключей. У ФНС это недокументированные эндпоинты, которые сайт вызывает сам: они могут измениться или начать требовать капчу без предупреждения.

| Источник | Как забираем | Что берём | Где хранится | Ограничения |
|---|---|---|---|---|
| **Реестр МСП** (rmsp.nalog.ru) | `data_fetching/rmsp_client.py`: `POST search-proc.json`, `mode=inn-list`. Один запрос ≈ 1 с | Название, тип (ЮЛ/ИП), категория (микро/малое/среднее), ОГРН, основной ОКВЭД, код региона, «вновь созданное», даты включения и исключения, контакты, лицензии, признаки (инновации, партнёрство, соцпредприятие), среднесписочная численность `od2_sschr` | `businesses` — текущее состояние; `registry_snapshots` (source=`msp`) — снимок для сравнения | ИНН нет в реестре → компанию подключить нельзя. `od2_sschr` есть не у всех: ключ пропадает и при нуле, и при отсутствии данных, поэтому это «неизвестно». Даты приходят со временем («10.07.2017 00:00:00») |
| **ЕГРЮЛ** (egrul.nalog.ru) | `data_fetching/egrul_client.py`: поиск → заказ выписки → ожидание → PDF → разбор PyMuPDF. Обычно 10–60 с | Полное и краткое название, адрес, КПП, ИФНС, руководитель (должность, ФИО, гражданство), дисквалификация (с, по, дата решения суда), участники и доли, «Дополнительные сведения» (отметки о недостоверности с датой записи), состояние (ликвидация, реорганизация, предстоящее исключение) с датой | Только `registry_snapshots` (source=`egrul`) | Капча уже после 4–5 выписок подряд (`CaptchaRequiredError`). Парсер проверен на выписках юрлиц; выписки ИП (ЕГРИП) не проверялись. Историю записей не читает |
| **ЕРКНМ** (proverki.gov.ru, открытые данные) | `data_fetching/erknm_client.py`: `GET /public/api/opendata/<год>/<месяц>` → ZIP → XML (~3,5 МБ архив, ~35 МБ XML, ~5 тыс. мероприятий). Берём прошлый, текущий и два следующих месяца — около двух минут | Проверки и профилактические визиты по ИНН: вид, контрольный орган, вид контроля, даты начала и окончания, статус; предостережения с текстом | Сразу события в `radar_events` (без снимков) | Поиск по ИНН на портале закрыт капчей — поэтому качаем выгрузки целиком. У ИП ИНН в выгрузке замаскирован — проверки ИП не находятся |
| **Официальный портал правовой информации** (publication.pravo.gov.ru) | `data_fetching/pravo_client.py`: `GET /api/Documents` за день по видам актов — федеральные законы, постановления Правительства, приказы ведомств, законы субъектов (~100 в день); поиск изменяемого акта по номеру и дате; PDF `GET /file/pdf` | Реквизиты, название, дата публикации, число страниц; PDF — во вложение к сообщению | `laws` — каждый разобранный акт (и нерелевантный, чтобы не разбирать повторно) | PDF — скан без текстового слоя |
| **Актуальные редакции** (actual.pravo.gov.ru:8000) | `pravo_client.text`: `card` → `redactions` → `redtext`, HTML → текст | Текст акта: какие акты он меняет, статьи НК и КоАП, дата вступления в силу | Не храним — только выводы в `laws` | Есть у законов и постановлений Правительства через 1–7 дней после публикации; у приказов ведомств и законов субъектов нет |
| **Пользователь** (кнопки в боте) | Вопросы «режим налогообложения» (всегда) и «численность» (если её нет в реестре или пользователь меняет её в `/profile`); вопрос-признак «да/нет» — когда вышел первый акт на тему, которую не видно в реестрах | Режим: ОСНО, УСН доходы, УСН доходы минус расходы, АУСН, ПСН (только ИП). Численность — диапазоном, храним нижнюю границу. Признаки: касса, маркировка, маркетплейсы, самозанятые, госзакупки, иностранные работники | `business_profiles` (одна строка на ИНН; признаки — в `flags`) | Ответ о численности важнее реестра и остаётся таким навсегда |
| **Каталог обязанностей** (код) | `radar/obligations.py`: 15 обязанностей, правила применимости, расписание сроков, перенос с выходных (праздники и постановления о переносах 2026 и 2027) | Сроки на 365 дней вперёд с текстами «что, куда, основание, штраф, почему вам» | `radar_events` (type=`deadline`, key `obl:<ИНН>:<код>:<номинальный срок>`) | Сверено с календарём бухгалтера на 2026 год; 2028 — после постановления о переносах |
| **MAX** | Отправитель сообщения (бот) и подписанный `initData` (мини-приложение, проверка подписи в `core/security.py`) | `max_user_id`, имя, username; в мини-приложении ещё язык и фото | `users` | — |
| **Экран «Уведомления»** | `PUT /api/settings/notifications` | Канал «чат», тихие часы, режим напоминаний; push и e-mail только хранятся | `users.notification_settings` | — |

**Не подключены** (заглушки или шаблоны есть, в работу не идут): блокировки счетов «БАНКИНФОРМ», сертификаты Росаккредитации, еженедельный дайджест.

**Таблицы:** `users` → `user_businesses` (многие-ко-многим, текущая компания — последняя подключённая) → `businesses`; `business_profiles` (ответы); `registry_snapshots` (сырые снимки МСП и ЕГРЮЛ, новый пишется только при изменении хэша); `radar_events` (сроки, события и состояния; `kind=once` уникален по ключу навсегда, `kind=condition` — одно открытое на ключ); `notifications` (очередь отправки, `dedup_key` не даёт отправить одно напоминание дважды); `laws` (разобранные акты pravo.gov.ru: темы, регион, изменяемые акты, даты вступления в силу). Таблица `feed_items` от прежней ленты законов в старых базах осталась, код её не использует.

## Когда что происходит

### По действию пользователя

| Действие | Что происходит сразу | Что в фоне |
|---|---|---|
| ИНН в боте (любой момент) или «Подключить» в мини-приложении | Проверка контрольной суммы → реестр МСП (не ответил — «Реестр МСП не отвечает, пришлите ИНН через пару минут», в мини-приложении — отдельный тост) → `businesses`, связь с пользователем: компания становится текущей, **прежняя отвязывается** и её напоминания в очереди отменяются → снимок МСП и события МСП (`process_msp`) → сроки обязанностей (`materialize_for`). В боте — карточка компании и первый вопрос; из мини-приложения бот сам пишет в чат следующий вопрос или итог (`continue_in_chat`) | `scan_in_background`: выписка ЕГРЮЛ и выгрузки ЕРКНМ. По одному ИНН — одна проверка за раз, ЕРКНМ — не чаще раза в день. Находки — сообщением в чат в течение минуты после обработки |
| Ответ на вопрос о режиме или численности | `business_profiles` → пересчёт сроков. В онбординге — следующий вопрос или итог; после онбординга — «Появились / Больше не касаются» | — |
| «Просканировать сейчас» (дашборд) и «Обновить» (профиль) | То же, что при подключении, но без смены текущей компании | ЕГРЮЛ и ЕРКНМ, как при подключении; пока идёт прошлая проверка, новая не запускается |
| Кнопки под сообщением | «Сделано» / «Не актуально» — статус события; «Сделано» у состояния реестра (исключение из МСП, недостоверность, ликвидация) — «Проверим по реестру»: если запись не исчезла, через интервал повтора бот снова напишет; «Завтра» — отдельное напоминание завтра в 09:00; «Подготовить документ» — .docx в чат | — |
| «Да» / «Нет» под вопросом-признаком («Вы принимаете оплату через кассу?») | Ответ — в `business_profiles.flags`, вопрос закрыт; «Да» — сразу акты на эту тему за 30 дней с PDF | — |
| «Выполнено» / «Подготовить документ» в мини-приложении | Статус задачи / .docx в чат | — |
| Сохранение настроек уведомлений | `users.notification_settings`; действует со следующей рассылки | — |

### По расписанию (планировщик в процессе бота, время московское)

| Когда | Задача | Что делает |
|---|---|---|
| Каждую минуту | `dispatch` | Отправляет очередь `notifications` в MAX. Сроки одной компании на одну дату — одним сообщением. В тихие часы ждёт (кроме демо). Выключен «Чат» — отменяет. Ошибка — до 3 попыток, потом `failed` |
| Ежедневно 03:00 (±10 мин) | `sync_egrul` | Выписка ЕГРЮЛ для каждого подключённого ИНН, минута между компаниями; капча — 15 минут паузы и повтор той же компании один раз |
| 11-го числа 04:00 | `sync_msp` | Реестр МСП (публикуется 10-го) для каждого ИНН: исключение, пропажа из реестра, смена категории; обновляет `businesses` |
| Ежедневно 04:30 | `check_inspections` | Одна загрузка выгрузок ЕРКНМ на все подключённые ИНН |
| Ежедневно 05:00 | `materialize` | Продлевает окно сроков на 365 дней вперёд, применяет изменения каталога |
| Ежедневно 07:00 | `ingest_laws` | Акты pravo.gov.ru за 10 дней: новые разбирает (`radar/laws.py`), сохраняет в `laws` и рассылает подходящим компаниям. «О внесении изменений…» без понятной темы ждёт текста и перепроверяется на следующий день. Около 3 минут |
| Ежедневно 09:00 | `queue_reminders` | Ставит напоминания на сегодня по настройке каждого пользователя: за 30, 7, 1 день и в день срока (по умолчанию), после срока — каждый день. Открытые состояния без срока (исключение из МСП, ликвидация, дисквалификация) — раз в `repeat_days` (7–30 дней) |
| При старте бота | `queue_reminders`, `start_laws` | Догоняет напоминания, если бот лежал в 09:00. Законы: таблица `laws` пустая — загружает акты за 30 дней без рассылки (для истории и `/demo_law`), иначе догоняет 07:00 |
| Пн 08:55, ежедневно 06:00, пн 05:30 | `weekly_digest`, `check_banks`, `check_certs` | Заглушки — ничего не делают |

Находки ночных проверок приходят по окончании тихих часов (по умолчанию в 08:00), новые законы — после 07:00, напоминания о сроках — в 09:00.

## Что умеет пользователь

### В чате с ботом

**Команды и сообщения**

| Что прислать | Когда работает | Что ответит бот |
|---|---|---|
| Кнопка «Начать» (первый запуск) или `/start` | Всегда | Нет компании — «Пришлите ИНН компании или ИП — 10 или 12 цифр…» и ждёт ИНН. Есть — продолжает с места остановки: следующий вопрос или итог со списком обязанностей |
| ИНН (10 или 12 цифр, пробелы по краям допустимы) | Всегда | Неверная контрольная сумма → «Некорректный ИНН…». Нет в реестре МСП → «Компанию с ИНН … не нашли в реестре МСП…». Реестр не ответил → «Реестр МСП (ФНС) сейчас не отвечает. Пришлите ИНН ещё раз через пару минут». Нашёлся → «Нашли вашу компанию» (карточка: название, ИНН, ОГРН, ОКВЭД, категория и численность, регион, режим, источник и дата) + кнопка «Открыть ленту обязанностей», затем вопросы. Другой ИНН при подключённой компании — делает его текущим, прежняя компания отвязывается |
| Любой другой текст, пока бот ждёт ИНН | До ИНН, если бот не перезапускался | «Некорректный ИНН. Введите 10 цифр…» (фото и стикеры тоже — раньше обработчик на них падал) |
| `/profile` | Есть компания | Карточка компании + кнопки «Изменить режим налогообложения», «Изменить численность», «Открыть ленту обязанностей». Без компании — просьба прислать ИНН |
| `/demo_remind` | Только при `DEBUG=true` | Сразу присылает напоминания по трём ближайшим открытым срокам текущей компании. Без сроков — «Открытых сроков нет — сначала подключите компанию» |
| `/demo_event knm` | Только при `DEBUG=true` | Имитация записи ЕРКНМ: «Запланирована проверка» Роспотребнадзора через 30 дней + задача в мини-приложении. Каждый вызов создаёт новую |
| `/demo_event msp_excluded` | Только при `DEBUG=true` | Имитация исключения из реестра МСП сегодняшней датой. Повторно — «Такое событие уже открыто. Оно закроется само, когда реестр перестанет его показывать…» |
| `/demo_event` с другим словом | Только при `DEBUG=true` | «Доступно: /demo_event knm, /demo_event msp_excluded» |

**Вопросы профиля (кнопки)**

- Режим: ОСНО · УСН доходы · УСН доходы минус расходы · АУСН · Патент (ПСН) — патент только у ИП, организации его не видят. Спрашивается всегда: в открытых реестрах режима нет.
- Численность: нет сотрудников · 1–15 · 16–25 · 26–35 · 36–100 · больше 100. Спрашивается, только если в реестре МСП нет среднесписочной численности. Границы — пороги обязанностей (есть сотрудники; квота для инвалидов при численности больше 35).
- Вопрос-признак (из ленты законов): «Вы принимаете оплату через кассу (ККТ)?», «…маркированные товары?», «…через маркетплейсы?», «…с самозанятыми?», «…в госзакупках?», «У вас работают иностранные граждане?» — кнопки «Да / Нет». Задаётся один раз, когда вышел первый акт на эту тему. «Да» → «Запомнили — присылаем, что вышло» и акты за 30 дней; «Нет» → «Запомнили: такие акты присылать не будем».
- После ответа: всплывающее «Сохранили: …». В онбординге — следующий вопрос или итог «📡 Радар настроен: N обязанностей» (список, 5 ближайших сроков, «Доступно при вашей численности» со ссылками на нормы, подсказка про `/profile`). После онбординга — «Профиль обновлён» и списки «Появились обязанности» / «Больше не касаются» или «Список обязанностей не изменился».

## Новые законы (pravo.gov.ru)

Главная функция: сообщить о вышедшем акте, только если он касается именно этой компании, и сразу дать официальный текст. OCR не нужен: тему акта бот определяет не по сканам, а по тому, **что акт меняет** (`radar/laws.py`, клиент — `data_fetching/pravo_client.py`).

**Как разбирается акт** (`worker.classify_act` → `laws.classify`):

1. **Название.** Словарь тем (ниже) по названию: «Об утверждении формы налоговой декларации по … упрощенной системы налогообложения» → УСН. Статьи Налогового кодекса и КоАП в названии → глава → тема: «…в статьи 166 и 168 части второй НК» → НДС (гл. 21), «статью 227-1» → НДФЛ иностранцев с патентом, 333.16–333.44 (госпошлина) — не налог на прибыль.
2. **Акты для государства отсекаются** регулярным выражением `NOT_BUSINESS`: госслужба и должности, сведения о доходах служащих, «территориальные органы», подведомственные учреждения, административные регламенты, бюджеты, награждения, соглашения, военные и спортивные акты. Прежний словарь по полному тексту здесь ошибался: «перечень должностных лиц Соцфонда» считал актом для работодателей.
3. **«О внесении изменений…» без понятной темы** («…в отдельные законодательные акты», «…в часть вторую НК», «…в постановление Правительства от 31 мая 2025 г. № 819»): изменяемый акт ищем на портале по номеру и дате («№ 819» → «Об утверждении Правил маркировки…»), а у законов и постановлений берём текст из «Актуальных редакций» и читаем только строки «Внести в …» / «В постановлении … "…"»: названия изменяемых актов и статьи НК/КоАП в разделах закона. Остальной текст поправок не читаем. Текста ещё нет — акт ждёт до следующего дня (окно 10 дней).
4. **Дата вступления в силу** — из фраз «Настоящий … вступает в силу …» («со дня официального опубликования», «по истечении десяти дней…», «с 1 марта 2027 г.»). Даты внутри самих поправок не берём.
5. **Законы субъектов** — только для компаний своего региона (регион — по органу в реквизитах: «Закон Амурской области» → 28). Региональные постановления и приказы не смотрим: это тарифы, субсидии и закупки учреждений.

**Ограничения.** Тема определяется по названию и изменяемым актам, а не по смыслу поправок: закон о кассах придёт всем, кто ответил «да» про кассу, даже если меняется узкий случай. Поэтому в сообщении есть оговорка и PDF. Точной «выжимки» что именно меняется без LLM нет — только список изменяемых актов и даты. Постановления без текста (изредка) и приказы, изменяющие приказ только по номеру без названия, ждут 10 дней и отбрасываются, если тема так и не нашлась.

## Допущения, которые стоит знать

- Документы к отчётам — памятки, а не бланки: коды форм (КНД) и периодов сверены 28.09.2026 по порядкам заполнения ФНС, реквизиты ЕНП — по памятке ФНС (с 01.04.2026 КПП получателя 770701001, КПП плательщика «0»). При смене приказов ФНС править `REPORTS` и `ENP_RECIPIENT` в `radar/documents.py`.
- Новые законы: тема акта — по названию, изменяемым актам и статьям НК/КоАП, не по смыслу поправок (см. [ограничения](#новые-законы-pravogovru)). Отраслевые темы — по основному ОКВЭД из реестра МСП. Законы субъектов — только своему региону. Первый запуск загружает 30 дней без рассылки; дальше рассылаются только акты, разобранные после подключения компании.
- Сроки и штрафы сверены с календарём бухгалтера на 2026 год. Если меняется НК — сверять заново. В каждом напоминании есть оговорка «сверяйтесь с календарём ФНС».
- Сроки создаются от сегодняшнего дня вперёд. Прошлые не создаются, чтобы при подключении не пугать просрочками, которые, скорее всего, уже закрыты.
- Численность: ответ пользователя (в `/profile`) важнее реестра МСП — реестр отстаёт на год. Нет данных в реестре → бот спрашивает диапазоном.
- События реестров со сроком (недостоверность, исключение, МВД, проверки) приходят сразу отдельным сообщением, а напоминания по ним начинаются со следующего дня — чтобы не было двух сообщений подряд. Если 6 месяцев с отметки о недостоверности уже прошли, задача сразу просрочена и напоминает каждый день: исключить компанию могут в любой момент.
- Изменение адреса бывает и без участия компании — при переименовании улицы. Сообщение об этом предупреждает.
- ЕРКНМ: мероприятие, которое уже началось, в задачи не попадает — о нём компания уже знает.
- Задачу, которая перестала касаться компании, удаляем вместе с её будущими сроками. Отметку «Не актуально» пересчёт профиля не трогает.
- Клиент MAX внедряет в мини-приложение скрипт, который оборачивает `Object.getOwnPropertyDescriptor`; повторно внедрённый, он зацикливается («Maximum call stack size exceeded» при открытии экрана с полем ввода — «Сменить компанию»). `miniapp/index.html` до всех скриптов закрепляет штатную функцию (через `Reflect`), попытки её заменить игнорируются. Проверено в Chrome с имитацией тройного внедрения; в живом MAX — после выкладки. Если экран всё же упадёт, вместо служебной страницы react-router — «Что-то пошло не так» и «Перезапустить».
- MAX может не дать написать пользователю, который ни разу не запускал бота. Тогда документ из мини-приложения вернёт 502 и тост «Не получилось». Кнопка `open_app` передаёт `web_app` (username бота) и `contact_id`.
