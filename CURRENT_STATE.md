## Как запустить

| Что | Команда |
|---|---|
| Всё в Docker | `docker compose up --build` (файл `compose.yaml`): postgres, API на :8000 (отдаёт и собранное мини-приложение), бот вместе с планировщиком — стартует после того, как API ответил на `/health`. Сборка с нуля — 75 с при обычной сети (при медленном registry.npmjs.org — до 290 с). Подробно, с переменными и портами, — [README.md](README.md#запуск) |
| Зависимости | Python — `requirements.txt`: все пакеты с точными версиями, его ставит Dockerfile. Выгружен из `uv.lock`: `uv export --no-hashes --no-dev --no-emit-project -o requirements.txt` (после правки `pyproject.toml` — сначала `uv lock`). Мини-приложение — `miniapp/package-lock.json` (`npm ci`) |
| API локально | из корня: `python backend/main.py` (`.env` читается из текущей папки; `DATABASE_URL` на localhost:5433 — обязателен, значения по умолчанию нет; без `SECRET_KEY` от 32 символов API не стартует). Схему БД при старте обновляют миграции Alembic. Статику берёт из `miniapp/build` — сначала `npm run build` в `miniapp/` |
| Бот локально | из корня: `python backend/bot/main_longpooling.py` |
| Мини-приложение | `cd miniapp && npm run dev`. Без `VITE_API_URL` работает на моках, подробности — [miniapp/README.md](miniapp/README.md) |
| Тесты | `python -m unittest discover -s tests`. Тесты с БД запускаются только при `TEST_DATABASE_URL=postgresql+asyncpg://…/пустая_база`: схему они пересоздают. Без Docker подойдёт локальный PostgreSQL: `initdb -D <папка> -U max -A trust`, `pg_ctl -D <папка> -o "-p 5544" start`, `createdb -p 5544 -U max maxtest` |

Демо-сроки поверх настоящих: `python backend/seed_demo_tasks.py <ИНН>` (на сервере: `docker compose exec backend python backend/seed_demo_tasks.py <ИНН>`). Добавляют просроченную, сегодняшнюю, ближайшие и выполненную задачи; в подписи у каждой «Демо · …», в правовом основании — «демо-данные», `source = demo` — их убирает и «🧹 Убрать демо-события» в `/demo`.

### Сервер

`https://hackaton267max.webtm.ru` — сервер 72.56.0.157 (`ssh root@72.56.0.157`), проект в `/opt/webapp_max_fastapi`. По голому IP HTTPS не работает: сертификат выписан на домен. Caddy (`/etc/caddy/Caddyfile`, сервис systemd) принимает HTTPS и проксирует на `127.0.0.1:8000`. Проект запущен через `docker compose`. Порты postgres (5433) и API (8000) открыты только на 127.0.0.1: пароль базы лежит в `compose.yaml`, а API снаружи доступен только через Caddy.

| Что | Команда на сервере |
|---|---|
| Выложить новую версию | `cd /opt/webapp_max_fastapi && git pull && docker compose up -d --build`. Миграции Alembic применяет `max_backend` при старте; бот ждёт, пока API ответит на `/health`. В `.env` сервера обязательны `MAX_TOKEN`, `SECRET_KEY` (от 32 символов) и `POSTGRES_PASSWORD`, иначе Compose не запустится. **Первая выкладка версии 29.09 (поздняя ночь)** — по шагам [из TODO](#todo): сменить пароль БД, дописать `.env` |
| Законы с pravo.gov.ru | После первого старта бот 5–10 минут загружает акты за 30 дней (без рассылки): `docker logs max_bot \| grep pravo`. Что отобрано за неделю — `/laws` в чате бота (при `DEMO=true`) или `docker compose exec postgres psql -U max -d maxapp -c "select published, topics, region, left(name, 80) from laws where topics <> '[]' order by published desc limit 20"` |
| Логи | `docker logs -f --tail 200 max_bot` (бот и планировщик), `max_backend` (API мини-приложения), `max_postgres`; `journalctl -u caddy -f` (HTTPS) |
| Что запущено | `docker ps` |
| Очередь сообщений | `docker compose exec postgres psql -U max -d maxapp -c "select id, label, status, scheduled_at, error from notifications order by id desc limit 20"` |

Локально бот с боевым `MAX_TOKEN` не запускать: два экземпляра делят между собой входящие сообщения.

## Когда что происходит

### По действию пользователя

| Действие | Что происходит сразу | Что в фоне |
|---|---|---|
| ИНН в боте (любой момент) или «Подключить» в мини-приложении | Проверка контрольной суммы → реестр МСП (не ответил — «Реестр МСП не отвечает, пришлите ИНН через пару минут», в мини-приложении — отдельный тост) → компанию уже ведёт другой пользователь — отказ (в боте — объяснение про Госуслуги, в приложении — «Эту компанию уже подключил другой пользователь MAX») → `businesses`, связь с пользователем: компания становится текущей, **прежняя отвязывается** и её напоминания в очереди отменяются → снимок МСП и события МСП (`process_msp`) → сроки обязанностей (`materialize_for`). В боте — карточка «Нашли вашу компанию… Всё верно?»; из мини-приложения бот сам пишет в чат следующий вопрос или итог (`continue_in_chat`) | `scan_in_background`: выписка ЕГРЮЛ и выгрузки ЕРКНМ. По одному ИНН — одна проверка за раз, ЕРКНМ — не чаще раза в день. Находки — пушем в чат в течение минуты после обработки |
| «✅ Да, всё верно» под карточкой | Карточка удаляется → вопрос о режиме (и о численности, если её нет в реестре) → итог «📡 Радар настроен» | — |

| Ответ на вопрос о режиме или численности | `business_profiles` → пересчёт сроков → следующий вопрос или итог | — |
| «Данные компании» → «Сохранить» (в любой момент) | Поправки → пересчёт сроков и тем законов → главная с тостом «Данные сохранены — обязанности пересчитали» | — |
| «Просканировать сейчас» (дашборд) и «Обновить» (профиль) | То же, что при подключении, но без смены текущей компании | ЕГРЮЛ и ЕРКНМ, как при подключении; пока идёт прошлая проверка, новая не запускается |
| Кнопки под пушем | Пуш удаляется из чата, приходит следующий из очереди. «📋 В список дел» — событие остаётся открытым и попадает на главную приложения (раздел «Список дел», если срока нет или он позже недели), напоминания о сроке идут дальше. «✅ Сделано» — статус «выполнено»; у состояния реестра (исключение из МСП, недостоверность, ликвидация) — «Проверим по реестру»: если запись не исчезла, через интервал повтора бот снова напишет. «🔕 Не актуально» — скрыть, больше не напоминать. «Открыть» — экран события в приложении (пуш остаётся) | — |

### По расписанию (планировщик в процессе бота, время московское)

| Когда | Задача | Что делает |
|---|---|---|
| Каждую минуту | `dispatch` | Отправляет очередь `notifications` в MAX **по одному пушу на пользователя**: следующий — после ответа на предыдущий или через сутки без ответа ([подробнее](#очередь-сообщений-по-одному)). Сроки одной компании на одну дату — одним пушем. В тихие часы ждёт (кроме демо). Выключен «Чат» — отменяет. Ошибка — до 3 попыток, потом `failed`; 403/404 от MAX — пользователь неактивен |
| Ежедневно 03:00 (±10 мин) | `sync_egrul` | Выписка ЕГРЮЛ для каждого подключённого ИНН, минута между компаниями; капча — 15 минут паузы и повтор той же компании один раз |
| 11-го числа 04:00 | `sync_msp` | Реестр МСП (публикуется 10-го) для каждого ИНН: исключение, пропажа из реестра, смена категории; обновляет `businesses` |
| Ежедневно 04:30 | `check_inspections` | Одна загрузка выгрузок ЕРКНМ на все подключённые ИНН |
| Ежедневно 05:00 | `materialize` | Продлевает окно сроков на 365 дней вперёд, применяет изменения каталога |
| Ежедневно 07:00 | `ingest_laws` | Акты pravo.gov.ru за 10 дней: новые разбирает (`radar/laws.py`), сохраняет в `laws` и рассылает подходящим компаниям. «О внесении изменений…» без понятной темы ждёт текста и перепроверяется на следующий день. Около 3 минут |
| Ежедневно 09:00 | `queue_reminders` | Ставит напоминания на сегодня по настройке каждого активного пользователя: за 30, 7, 1 день и в день срока (по умолчанию), после срока — каждый день. Открытые состояния без срока (исключение из МСП, ликвидация, дисквалификация) — раз в `repeat_days` (7–30 дней) |
| При старте бота | `queue_reminders`, `start_laws` | Догоняет напоминания, если бот лежал в 09:00. Законы: таблица `laws` пустая — загружает акты за 30 дней без рассылки (для истории и `/demo_law`), иначе догоняет 07:00 |

Находки ночных проверок приходят по окончании тихих часов (по умолчанию в 08:00), новые законы — после 07:00, напоминания о сроках — в 09:00. «Сегодня» везде считается по Москве (`planner.today_msk`), а не по UTC контейнера.

## Бот и мини-приложение: кто что делает

Решение от 29.09.2026: **бот — короткие пуши и регистрация, всё остальное — в приложении.**

| | Бот (чат MAX) | Мини-приложение |
|---|---|---|
| Регистрация | ИНН → «Нашли вашу компанию» со всем найденным → «Всё верно?» → вопросы режима и численности кнопками → короткий итог | Подключение по ИНН или QR; «Данные компании» — исправить найденное |
| Что-то случилось (срок, закон, запись в реестре) | Пуш: иконка важности, что случилось, главная дата — 2–3 строки. Одно решение кнопкой: «В список дел», «Сделано», «Не актуально» — или «Открыть» | Экран события: что это значит, почему вам, что сделать, основание и источник, «Подготовить документ», «Выполнено», «В список дел» |
| История | Отвеченные пуши удаляются — в чате только то, что ждёт решения | Лента (колокольчик): всё, о чём писал бот, за 90 дней, и чем кончилось; главная: «Сегодня», «На неделе», «Список дел»; календарь |
| Данные и настройки | `/profile` — карточка и кнопка «Изменить данные» (в приложение) | «Данные компании», «Уведомления», тема |
| Документы | Файл .docx приходит в чат | Кнопка «Подготовить документ» |

Полные тексты сообщений (`radar/templates.py`, шаблоны без префикса) теперь — источник разделов экрана события: `tasks.template_sections` режет их по заголовкам «Что произошло», «Что это значит», «Что сделать», «Ваши права». В чат уходят короткие шаблоны `push.<тип>`.

**Вопросы профиля (кнопки)**

- Режим: ОСНО · УСН доходы · УСН доходы минус расходы · АУСН · Патент (ПСН) — патент только у ИП, организации его не видят. Спрашивается, пока не указан: в открытых реестрах режима нет.
- Численность: нет сотрудников · 1–15 · 16–25 · 26–35 · 36–100 · больше 100. Спрашивается, только если в реестре МСП нет среднесписочной численности. Границы — пороги обязанностей (есть сотрудники; квота для инвалидов при численности больше 35).
- Вопрос-признак (из ленты законов): «Вы принимаете оплату через кассу (ККТ)?», «…маркированные товары?», «…через маркетплейсы?», «…с самозанятыми?», «…в госзакупках?», «У вас работают иностранные граждане?» — кнопки «Да / Нет». Задаётся один раз, когда вышел первый акт на эту тему. «Да» → «Запомнили — присылаем, что вышло» и акты за 30 дней; «Нет» → «Запомнили: такие акты присылать не будем».
- Итог онбординга — коротко: «📡 Радар настроен: N обязанностей», «Ближайший срок — 26.10: … (…)», для патента без срока — «Укажите срок патента в «Данных компании»», «Список, календарь и документы — в приложении…» + «Открыть приложение». Список обязанностей и льготы по численности — в приложении.

## Очередь сообщений: по одному

Бот не присылает пачку. У каждого пользователя в чате не больше одного сообщения, которое ждёт ответа (`users.awaiting_mid`), — всё остальное ждёт в очереди `notifications`:

- **Когда приходит следующее.** После ответа на текущее: любая кнопка под ним, кроме «Открыть» и ссылок. Бот удаляет отвеченное сообщение (`bot.delete_message`) и присылает следующее (`worker.answered`). «Выполнено» и «В список дел» в приложении работают так же (`worker.handled_in_app`): пуш о событии удаляется, приходит следующий. Карточка «Всё верно?», вопросы профиля, «Да / Нет» и карточки `/demo` тоже ждут ответа; сохранение «Данных компании» считается ответом на карточку и вопросы профиля.
- **Порядок.** Сначала критичное (🔴: недостоверность, исключение, дисквалификация), дальше — в порядке появления. Сроки одной даты — одним пушем. Если за время ожидания об одной задаче накопилось несколько напоминаний («через 7 дней», «через 1 день»), приходит только последнее.
- **Сколько ждёт.** Сутки. Не ответили за сутки — приходит следующее (иначе критичное застряло бы за неотвеченным напоминанием), и ожидание начинается заново. Неотвеченное старое сообщение остаётся в чате.
- **Что не ждёт очереди.** Прямые ответы на действия пользователя: итог онбординга, `/profile`, документ, PDF к акту, подсказка на произвольный текст, первая карточка `/demo`.
- **Внизу сообщения** — «Ещё N сообщений — пришлю по одному, когда ответите на это», если в очереди есть ещё.
- **Заблокировал бота.** MAX ответил 403 или 404 — пользователь `is_active = false`, его очередь отменена, новые напоминания не ставятся. Снова пишем после `/start` или входа в мини-приложение.

## Новые законы (pravo.gov.ru)

Главная функция: сообщить о вышедшем акте, только если он касается именно этой компании, и сразу дать официальный текст. OCR не нужен: тему акта бот определяет не по сканам, а по тому, **что акт меняет** (`radar/laws.py`, клиент — `data_fetching/pravo_client.py`). В чат — короткий пуш и PDF, на экране события — что меняется, почему вам, что сделать и ссылка на текст.

**Как разбирается акт** (`worker.classify_act` → `laws.classify`):

1. **Название.** Словарь тем (ниже) по названию: «Об утверждении формы налоговой декларации по … упрощенной системы налогообложения» → УСН. Статьи Налогового кодекса и КоАП в названии → глава → тема: «…в статьи 166 и 168 части второй НК» → НДС (гл. 21), «статью 227-1» → НДФЛ иностранцев с патентом, 333.16–333.44 (госпошлина) — не налог на прибыль.
2. **Акты для государства отсекаются** регулярным выражением `NOT_BUSINESS`: госслужба и должности, сведения о доходах служащих, «территориальные органы», подведомственные учреждения, административные регламенты, бюджеты, награждения, соглашения, военные и спортивные акты. Прежний словарь по полному тексту здесь ошибался: «перечень должностных лиц Соцфонда» считал актом для работодателей.
3. **«О внесении изменений…» без понятной темы** («…в отдельные законодательные акты», «…в часть вторую НК», «…в постановление Правительства от 31 мая 2025 г. № 819»): изменяемый акт ищем на портале по номеру и дате («№ 819» → «Об утверждении Правил маркировки…»), а у законов и постановлений берём текст из «Актуальных редакций» и читаем только строки «Внести в …» / «В постановлении … "…"»: названия изменяемых актов и статьи НК/КоАП в разделах закона. Остальной текст поправок не читаем. Текста ещё нет — акт ждёт до следующего дня (окно 10 дней).
4. **Дата вступления в силу** — из фраз «Настоящий … вступает в силу …» («со дня официального опубликования», «по истечении десяти дней…», «с 1 марта 2027 г.»). Даты внутри самих поправок не берём.
5. **Законы субъектов** — только для компаний своего региона (регион — по органу в реквизитах: «Закон Амурской области» → 28; регион компании — из реестра или поправленный в «Данных компании»). Региональные постановления и приказы не смотрим: это тарифы, субсидии и закупки учреждений.

**Темы** (`TOPICS`; «почему вам» — функция профиля, как `applies` у обязанностей):

| Тема | Кого касается |
|---|---|
| УСН, АУСН, патент | Этот режим (ответ в боте или «Данные компании») |
| НДС | ОСНО; УСН — с 2025 года упрощенцы плательщики НДС |
| Налог на прибыль | Организации на ОСНО |
| НДФЛ | Есть сотрудники (налоговый агент); ИП на ОСНО |
| Страховые взносы, персучёт, ЕФС-1 | Есть сотрудники; ИП не на АУСН («за себя») |
| Трудовой кодекс, охрана труда, СОУТ, МРОТ | Есть сотрудники |
| Квота для инвалидов | Численность больше 35 |
| Бухучёт | Организации |
| Общие правила: регистрация ЮЛ и ИП, закон о МСП, электронная подпись, персональные данные, закон о контроле (248-ФЗ), часть первая НК (уплата, декларации, проверки, ответственность), КоАП 15.5/15.6/15.11 | Все |
| Лицензирование | Есть лицензии (реестр МСП или «Данные компании») |
| Касса, маркировка, маркетплейсы, самозанятые, госзакупки, иностранные работники | Ответ «да» на вопрос-признак или в «Данных компании» (маркетплейсы — ещё и ОКВЭД 47.91) |
| Алкоголь, табак, торговля, общепит, гостиницы, пассажиры, грузоперевозки, туризм, лекарства, защита прав потребителей | Основной ОКВЭД из реестра МСП или поправленный (дополнительные не смотрим: у ООО их часто десятки «на всякий случай») |

**Проверено на настоящих актах** (выгрузки портала сохранены при разработке): все акты за 1–27 сентября 2026 (федеральные, Правительство, ведомства, законы субъектов) и федеральные законы за июнь–август 2026 — около 1 150 актов. Про бизнес — 60: 41 по названию, 7 по найденному изменяемому акту, 12 по тексту (например, 292-ФЗ «…часть вторую НК» → НДС, прибыль, НДФЛ; 295-ФЗ «…в КоАП» → маркетплейсы и табак; постановление «…в некоторые акты» → лицензирование торговли табаком). Живой прогон за 10 дней для кафе в Москве на УСН: 3 минуты, одно сообщение (изменения ПБУ 18/02 — бухучёт организаций) с PDF 107 КБ. Тест классификатора — `tests/test_laws.py` на настоящих названиях и тексте в формате портала.

**Ограничения.** Тема определяется по названию и изменяемым актам, а не по смыслу поправок: закон о кассах придёт всем, кто ответил «да» про кассу, даже если меняется узкий случай. Поэтому на экране события есть оговорка и PDF. Точной «выжимки» что именно меняется без LLM нет — только список изменяемых актов и даты. Постановления без текста (изредка) и приказы, изменяющие приказ только по номеру без названия, ждут 10 дней и отбрасываются, если тема так и не нашлась. Компания получает акты, разобранные после её подключения: прошлые 30 дней не досылаем — сопровождаем с момента регистрации.

## Допущения, которые стоит знать

- **Что проверить бухгалтеру (ревью, п. 8)** — сделано по НК РФ и разъяснениям ФНС, но стоит сверить:
  - **АУСН с сотрудниками.** Считаем, что НДФЛ за сотрудников считает и перечисляет банк (так по умолчанию по закону № 17-ФЗ), поэтому уведомлений по НДФЛ и уплаты ЕНП у АУСН нет. Если компания платит НДФЛ сама — эти две обязанности ей нужны, а бот их не покажет. Проверить: как в вашем банке настроена АУСН.
  - **Авансы НДФЛ у ИП на ОСНО.** Сроки уведомлений (25.04, 25.07, 25.10) и уплаты (28.04, 28.07, 28.10, налог за год — 15.07) — по ст. 227 НК РФ. КБК в уведомлении пустой: он зависит от суммы дохода (до 2,4 млн ₽ и свыше — разные КБК), сверить в личном кабинете ИП.
  - **Патент.** Сроки — по п. 2 ст. 346.51 НК РФ от срока, который указал пользователь. Сумму патента бот не считает.
- Документы к отчётам — памятки, а не бланки: коды форм (КНД) и периодов сверены 28.09.2026 по порядкам заполнения ФНС, реквизиты ЕНП — по памятке ФНС (с 01.04.2026 КПП получателя 770701001, КПП плательщика «0»). При смене приказов ФНС править `REPORTS` и `ENP_RECIPIENT` в `radar/documents.py`.
- Новые законы: тема акта — по названию, изменяемым актам и статьям НК/КоАП, не по смыслу поправок (см. [ограничения](#новые-законы-pravogovru)). Отраслевые темы — по основному ОКВЭД. Законы субъектов — только своему региону. Акты, вышедшие до подключения компании, не досылаются.
- Сроки и штрафы сверены с календарём бухгалтера на 2026 год. Если меняется НК — сверять заново.
- Сроки создаются от сегодняшнего дня вперёд. Прошлые не создаются, чтобы при подключении не пугать просрочками, которые, скорее всего, уже закрыты.
- Поправки пользователя («Данные компании») важнее реестра. Совпадающее с реестром не храним: когда ФНС обновит данные, они подтянутся сами.
- Одну компанию ведёт один аккаунт MAX (ревью, п. 3). Кто первым подключил ИНН, тот и владелец, пока не подключит другую компанию. В рабочей версии — подтверждение через Госуслуги.
- Бот присылает по одному пушу и ждёт ответа до суток — см. [очередь](#очередь-сообщений-по-одному). Отвеченное удаляется из чата: история — в ленте мини-приложения.
- События реестров со сроком (недостоверность, исключение, МВД, проверки) приходят сразу отдельным пушем, а напоминания по ним начинаются со следующего дня. Если 6 месяцев с отметки о недостоверности уже прошли, задача сразу просрочена и напоминает каждый день.
- Изменение адреса бывает и без участия компании — при переименовании улицы. Экран события об этом предупреждает.
- ЕРКНМ: мероприятие, которое уже началось, в задачи не попадает — о нём компания уже знает.
- Задачу, которая перестала касаться компании, удаляем вместе с её будущими сроками. Отметку «Не актуально» пересчёт профиля не трогает.
- Клиент MAX внедряет в мини-приложение скрипт, который оборачивает `Object.getOwnPropertyDescriptor`; повторно внедрённый, он зацикливается. `miniapp/index.html` до всех скриптов закрепляет штатную функцию. Если экран всё же упадёт — «Что-то пошло не так» и «Перезапустить».
